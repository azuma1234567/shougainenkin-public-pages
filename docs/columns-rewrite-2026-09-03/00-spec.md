## 1. 記事ごとの編集ルール(原稿担当: Fable)

### 1-1. リード(冒頭)
- h1 の直下に「**この記事の結論**」を3〜5行で置く(新フィールド `lead`)。読者の問いへの答え・いちばん大事な数字か期限・次にすること、の順。
- 既存の書き出し(情景・共感の段落)は残してよいが、結論の**あと**に置く。
- 「先に結論」「結論を先に」という h2 がすでにある記事は、その内容を lead に移し、h2 は消す。

### 1-2. 太字
- 文の途中の太字は**すべて外す**(強調は文の構造で出す)。
- 残すのは、段落頭の見出し代わり(`**質問1:…**`、`**ステップ3:…**`)、表の中、FAQ の `**Q.**` だけ。
- 段落頭の見出し代わりは、可能なら `###` に格上げする(目次に出る)。

### 1-3. 導線(すべての記事に、該当するものを)
- **道具**: 記事の中で読者が「自分の場合はどうか」と思う箇所に、該当する道具への1行を置く。文言は道具の質問形をそのまま使う:
  - 私は何級くらい? → /dougu/mitate
  - いくらもらえる? → /dougu/kingaku
  - 何をそろえればいい? → /dougu/shorui
  - どこに出せばいい? → /dougu/madoguchi
  - 申立書を、自分で書きたい → /dougu/moushitatesho
- **誤解カード**: 記事の論点に対応する誤解カードを、本文中の該当箇所に `→ 「…」は誤解です(/gokai/slug)` の形で。1記事1〜3枚。
- **裁決事例**: 「裁決例があります」「〜と判断された事案があります」は、**ID付きの1段落**に置き換える(誤解カードと同じ形式: `**病名・請求種別(年代、ID)** — 要旨。` + `→ ほかの実例も読む(/jitsurei)`)。IDは `data/saiketsu-cases-2026-08-26.json` の verified のみ。置き換えられる裁決が無ければ、その文は**消す**。
- 「実例」「〜さんの場合」など創作の例(アキさん・ミキさん等)は残してよい。ただし裁決と混ざらないよう、裁決の段落には必ずIDを付ける。

## 2. 記事の見た目(実装担当: Claude Code)

いまの記事ページは、太字だらけの長文が一枚の帯で続く。次の形にする。**トップ・ハブ・道具のページと同じ platform の見た目**に寄せる。

1. **結論の箱**: h1 の下に `lead` を薄い背景の箱で。「この記事の結論」の小見出し + 3〜5行。
2. **目次**: 結論の箱の下に h2 の目次(折りたたみ、モバイルは閉じた状態)。
3. **本文の幅と行間**: 本文 680〜720px、`line-height 1.9`、段落間 1.2em、h2 の上に 2.4em。h2 は左の帯線で区切る(platform の `p-section` に合わせる)。
4. **段落頭の太字**: `**ラベル:**` で始まる段落は、太字ではなく `h3` 相当の見た目(少し大きく、色は見出し色)にする。文中の `<strong>` は原稿側で消すので、CSS では色を付けない。
5. **道具の1行**: 原稿の `→ 私は何級くらい?(/dougu/mitate)` を、道具の色(data/dougu.ts の accent)を左に付けた1行カードで出す(JibunCard の小型版)。
6. **裁決の段落**: `**…(年代、ID)** —` の段落を `gokai-case` と同じ見た目にし、IDを厚労省PDFの外部リンクに置き換える(誤解カードと同じ実装を再利用)。
7. **誤解カードの1行**: `→ 「…」は誤解です(/gokai/…)` を、誤解カードの色で1行に。
8. **表**: 横スクロールの容器に入れる(いま 375px で切れる表がある)。
9. **FAQ**: Q を h3、A を段落。FAQPage JSON-LD は今のまま。
10. **出典**: URL をリンクに。`data-yougo-skip`。
11. **日付**: `dateModified` を「最終確認日」として h1 の下に(PageDate と同じ書式)。

## 3. 実装の段取り(Claude Code)

1. `content/columns/*.ts` の本文を、`docs/columns-rewrite-2026-09-03/articles/<slug>.md` から生成する `scripts/import-columns.mjs` を作る(誤解カードの import と同じ考え方)。frontmatter: `slug / lead(複数行) / dateModified`。本文はいまと同じ Markdown。`faqs` は本文の「よくある質問」から抜く(既存の faqs 配列と同じ形)。
2. `Column` 型に `lead?: string[]` を足す(lib/columns.ts は生成の対象外。lead は content 側から export する)。
3. `MarkdownArticle` に §2 の 4・5・6・7・8 のブロックを足す。新しい記法は3つだけ: `→ ラベル(/dougu/…)`、`→ 「…」は誤解です(/gokai/…)`、`**…(年代、ID)** — …`。
4. `ColumnArticle` に §2 の 1・2・3・9・10・11。
5. `apply2026Amounts` を通す2記事は、生成後も同じ関数を通す。
6. verify: `scripts/verify-columns.mjs` を新設。①47記事すべてに lead(3〜5行) ②本文の文中太字0(段落頭・表・Qは可) ③`/dougu/` リンクが全記事に1本以上(3記事を除く) ④裁決IDが verified に存在 ⑤内部リンクが全部 `isPublishedInternalPath` ⑥金額が amounts-derive で説明できる ⑦禁止文字列なし ⑧h1・metaTitle・slug が作業前と一致 ⑨FAQPage JSON-LD が全記事に ⑩375px で横スクロールなし。
7. `npm run prelaunch:check` でページ数不変。
8. 3記事の検査: `moushitatesho-a4-insatsu` は h2 の並び・内部リンク先の集合・アプリ導線の文言が作業前と一致すること(バイト一致はもう求めない)。
9. コミットは「feat(columns): 記事の見た目」「content(columns): batch N」「test(columns): verify」に分ける。push は batch ごと。
