## §1 判断1: 裏面の就労ブロックは入力UIに足す(足してよい)

設計 §6-2「足すのはこれだけ」が間違っていた。§10-6 で職種〜理由を要求しているのに、入力側に無いことを見落としていた。私の設計ミス。足す。

`BackSide` 型(`data/moushitatesho/types.ts`)は既に `work / job / commuteMethod / commuteHours / commuteMinutes / daysPrev / daysPrevPrev / cond / reasons / reasonsOther` を持っているので、データと描画は触らず、**入力UIだけ**を足す。

既存「裏面」のステップに、S=0(障害認定日頃)と S=1(現在)のそれぞれで、日常生活の1〜4の**前**に「就労の状況」を置く。様式の順番どおり:

| 順 | 入力 | 型 | 様式の欄 |
|---|---|---|---|
| 1 | 「働いていましたか(いますか)」 はい/いいえ | `work` | 様式に無い。UI の分岐用。**紙には何も出さない** |
| 2 | はい → 職種 | `job` 1行テキスト(枠 lines 2) | 職種 |
| 3 | はい → 通勤方法 | `commuteMethod` 1行 | 通勤方法 |
| 4 | はい → 通勤時間(片道) 時間・分 | `commuteHours` `commuteMinutes` 数字2桁 | 通勤時間 |
| 5 | はい → 出勤日数 前月・前々月 | `daysPrev` `daysPrevPrev` 数字2桁 | 出勤日数。見出しに S=0 は「障害認定日の前月・前々月」、S=1 は「請求日の前月・前々月」と書く(様式の文言) |
| 6 | はい → 仕事中や仕事が終わった時の身体の調子 | `cond` 複数行(枠の lines に合わせる) | 身体の調子 |
| 7 | いいえ → 理由 ア〜オ(複数可) | `reasons` チェック | 理由 |
| 8 | いいえ・オ → その理由 | `reasonsOther` 1行 | オ(理由) |

- ラベルは `WORK_REASONS_NINTEI / GENZAI` をそのまま使う(S=0 は過去形、S=1 は現在形。定数は既にある)。
- `work` が `null`(未回答)なら 2〜8 を出さない。「はい」で 7〜8 は出さない、「いいえ」で 2〜6 は出さない。ただし**保存済みの値は消さない**(切り替えても戻せる)。紙に出すのは、はい→2〜6、いいえ→7〜8 だけ。
- 「はい」でも通勤時間・出勤日数が空なら空欄のまま(0 を書かない)。
- §6-3 の「収まらない」表示は、職種・身体の調子・その他の理由にも付ける(text スロット全部が対象。§3 参照)。
- 足さないもの: 例文、「よくある職種」の候補、就労の可否についての説明文。入力欄と様式の見出し語だけ。

## §2 判断2: No. ― 枚中 は記載要領に従う(1枚なら空欄)

記載要領(05.pdf)「複数枚記入した場合は、順番と記入した枚数を数字で記入してください」が正。設計 §5「続紙が無くても 1 ― 1 と書く」は取り下げる。

- 総枚数 = 1(続紙なし)→ 本紙の No. と 枚中は**両方とも空欄**。
- 総枚数 ≥ 2 → 本紙 No.1、続紙 k は No. k+1、枚中は総枚数。今の実装のとおり。
- サンプル `minimal` `typical` は空欄、`seven` `max` は入る。§9-2 の検査もこの規則で。

## §3 判断3: 電話番号は印字の「― ―」の間に3分割で置く

設計 §4-2「ハイフン込みで左から書く」は取り下げる。様式に ― が印字されている以上、その間に置くのが「様式どおり」。§9-2 の2番(印字と交差しない)とも両立する。

### 3-1 入力

- 入力欄は1つのまま(`seikyuusha.tel` `daihitsu.tel`)。placeholder は `090-1234-5678`。
- 分割規則: ハイフン(半角 `-`、全角 `－`、`ー`)で区切って**2〜3個**に分かれればそれを使う。ハイフンが無く数字だけのとき、11桁 → 3-4-4、10桁で先頭が `0120` `0800` → 4-2-4、それ以外の10桁 → 分割できないので「市外局番の区切りにハイフンを入れてください」を入力欄の下に1行(赤くしない)。分割できない間は紙に**書かない**(左詰めで書くと ― と重なる)。
- 2個に分かれたときは、1番目を左の区画、2番目を右の区画に置き、中央の区画は空。
- 電話番号の分割は `lib/moushitatesho-tel.ts` に関数として切り出し、テストを書く(11桁・10桁フリーダイヤル・ハイフン3種・全角数字→半角・空・4個以上に分かれた入力は「そのまま3個目に残りを結合」)。

### 3-2 描画

- 電話番号の text スロット(本紙裏 請求者 / 本紙裏 代筆者 / 続紙裏 請求者 / 続紙裏 代筆者)を、**3つの区画**に分ける。区画の境界は印字された ― の x 座標で決める: 左区画 = 欄の左端〜1本目の ― の左端、中区画 = 1本目の右端〜2本目の左端、右区画 = 2本目の右端〜欄の右端。上下は現状の y/h のまま。各区画の**中央揃え**、10.5pt(fontPt に従う)。
- ― の x は `01.pdf`(本紙裏 2か所)と `03.pdf`(続紙裏、報告にあった x 142.9 / 160.01 と、代筆者の分)を `scripts/measure-form.py` で実測し、`measure.md` / `measure-cont.md` に追記する。
- `layout.ts` に `TelSlot`(`segments: [{x,w},{x,w},{x,w}]`)を足すか、text スロット3つを並べるかは Codex が決めてよい。どちらでも §9-2 の検査対象になること。
