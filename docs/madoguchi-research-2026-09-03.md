# 年金事務所を探す — 窓口データの下調べ (2026-09-03)

`docs/madoguchi-tool-design-2026-09-02.md` §5「窓口データの作り方」の実装に先立って、機構サイトの構造・取れる項目・落とし穴・設計書の直すべき点を確認したもの。**全件の取得は Codex が行う**(§6 のスクレイパー仕様)。この文書は一次資料を今日の時点で見た結果で、確認日はすべて 2026-09-03。

## §1 結論(先に)

1. データは機構サイトの **3種類のページ**から作る。都道府県ページ(一覧)→ 事務所ページ(住所・電話)→ **管轄区域ページ(市区町村との対応)**。管轄は事務所ページには無い。
2. **管轄は「健康保険・厚生年金保険」と「国民年金」で別の事務所になることがある。** 設計書の `jurisdiction: string[]` では足りない。2本に分ける(§3)。これがいちばん大きい修正。
3. 街角の年金相談センターは**全国80か所**(全国社会保険労務士会連合会の公表値)。管轄は無く、誰でもどこでも使える。年金事務所と分けて出す設計はそのまま。
4. §4 の予約情報は今日の公式ページと一致。ただし設計書の「照査番号」は誤記で、公式は**「照会番号」**。
5. 市区町村の選択肢は、機構の管轄表から作らず、**総務省の全国地方公共団体コード(1,741市区町村)を正**にして、そこへ管轄を当てる(§4)。管轄表は「西多摩郡」「大島支庁管内」のような単位で書かれていて、そのままでは町村名で探せない。

## §2 機構サイトの構造(確認済み)

### 2-1 入口と都道府県ページ
- 入口: `https://www.nenkin.go.jp/section/soudan/index.html`(`/section/soudan/` は末尾スラッシュだとリダイレクトが回るので、`index.html` まで書く)
- 都道府県ページ: `https://www.nenkin.go.jp/section/soudan/{slug}/index.html`
- slug は47個。**新潟は `nigata`**(niigata ではない)。全リスト:
  `hokkaido aomori iwate miyagi akita yamagata fukushima ibaraki tochigi gunma saitama nigata nagano chiba tokyo kanagawa yamanashi toyama ishikawa gifu shizuoka aichi mie fukui shiga kyoto osaka hyogo nara wakayama tottori shimane okayama hiroshima yamaguchi tokushima kagawa ehime kochi fukuoka saga nagasaki kumamoto oita miyazaki kagoshima okinawa`
- 都道府県ページには**年金事務所と街角の年金相談センターが同じ表**に並ぶ。表にあるのは名称とリンクだけで、住所・電話は無い。
- 事務所ページのURLは `{slug}/{事務所名ローマ字}.html`(例 `tokyo/adachi.html`)。**街角のURLは規則が揺れる**(`tokyo/adachioffice.html`、`hiroshima/centerhiroshima.html`)。URLを推測せず、都道府県ページの表からリンクを辿ること。

### 2-4 管轄区域ページ(東京・神奈川で確認)
- URL: `https://www.nenkin.go.jp/section/soudan/kankatsu/kankatsu_{slug}.html`(slug は 2-1 と同じ)
- 表の列: **事務所名(短い呼称) / 健康保険・厚生年金保険 / 国民年金**。まれに「船員保険」列(新宿=東京都)。
- **事務所名は短い呼称**(「千代田」「横浜中」)で、事務所ページの名称(「千代田年金事務所」)と突き合わせる正規化が要る。
- 同じ事務所でも2列の中身が違う例:
  - 新宿: 厚年 = 新宿区 杉並区 中野区 / 国年 = 新宿区。杉並・中野は国年だけ自区の事務所(杉並・中野)
  - 横浜中: 厚年 = 西区 中区 南区※2 磯子区 金沢区 港南区 / 国年 = 西区 中区
  - 横浜南: 厚年 = **空** / 国年 = 南区※2 磯子区 金沢区 港南区
- 政令市の区は **「鶴見区」のように市名なし**で書かれる。脚注「※1 横浜市緑区」「※2 横浜市南区」で相模原市の緑区・南区と区別している。
- 郡・支庁は **「西多摩郡」「大島支庁管内」** のように束ねて書かれる。町村名は出てこない。

## §3 設計書の直すべき点

### 3-1 `Office` 型(§5-2)
```ts
type Office = {
  id: string; pref: string;               // pref は slug(tokyo)。表示名は別表
  kind: 'nenkin' | 'machikado';
  sub?: 'center' | 'office';              // 街角のみ
  name: string;                           // 機構の表記のまま(読み付き)
  nameShort: string;                      // 読み・「年金事務所」を落とした呼称。管轄表との突合キー
  zip: string; addr: string;
  tel: string; telNote?: string; fax?: string;
  hours?: { weekday: string; weekStartExt?: string; secondSat?: string; closed: string };
  access?: string; parking?: string;
  jurisdictionKousei: string[];           // 健康保険・厚生年金保険(年金事務所のみ。空あり)
  jurisdictionKokumin: string[];          // 国民年金(年金事務所のみ)
  url: string; checkedOn: string;
};
```
共通番号(ねんきんダイヤル等)は `data/madoguchi/common.ts` の定数。

### 3-2 §3 の判定と、出す事務所の対応
| 判定 | 提出先 | 「窓口を探す」で出す事務所 |
|---|---|---|
| 厚生年金 → 障害厚生年金 | 年金事務所 | **`jurisdictionKousei` に市区町村が入っている事務所** |
| 国民年金 / 20歳前 → 障害基礎年金 | 市区町村の国民年金窓口(第3号は年金事務所) | 市区町村窓口を案内しつつ、相談先として **`jurisdictionKokumin` の事務所** |
| わからない | 両方 | 両方の事務所(同じなら1件) |

例: 横浜市南区の人が障害厚生年金 → 横浜中。国民年金の相談 → 横浜南。杉並区の人が障害厚生年金 → 新宿。**この違いを出さないと、行き先を間違える**。設計書 §1 の「提出先を間違えて出し直しになる人」がここでも起きる。

### 3-3 逆引き索引(§5-3)は制度ごとに2本
`byMunicipality: { [code: string]: { kousei: officeId | null; kokumin: officeId | null } }`。キーは総務省の団体コード(§4)。

### 3-4 誤記
§4 表「電話で必要なもの」の **照査番号 → 照会番号**。公式(予約受付専用電話ページ)は「照会番号（各種通知書等に記載のもの）」。

## §4 市区町村の選択肢は総務省コードを正にする

理由: 管轄表は「西多摩郡」「大島支庁管内」「相模原市」(区なし)のような粒度で、利用者が自分の町村名で探せない。

1. 総務省「全国地方公共団体コード」(`https://www.soumu.go.jp/denshijiti/code.html`)の最新 Excel から、**都道府県 + 市区町村 1,741 件**(政令市は区まで、郡は町村まで)を `data/madoguchi/municipalities.json` に落とす。列: `code, pref, name, kind('市'|'区'|'町'|'村'|'特別区'), district?(郡名), city?(政令市名)`。
2. 管轄表の各エントリを次の規則で市区町村コードに展開する:
   - 「◯◯市」「◯◯区」(特別区)→ そのコード
   - 政令市の「◯◯区」(市名なし)→ **その事務所の住所の市**、または脚注(※)の市を付けて特定。脚注は必ず読む
   - 「◯◯郡」→ その郡に属する町村すべて
   - 「◯◯支庁管内」(東京都の島しょ)→ 手書きの対応表 `data/madoguchi/manual-map.json` で町村に展開(大島支庁=大島町・利島村・新島村・神津島村、三宅支庁=三宅村・御蔵島村、八丈支庁=八丈町・青ヶ島村、小笠原支庁=小笠原村)。北海道の「◯◯振興局管内」が出たら同様
   - 展開できなかった文字列は **`unresolved.json` に落として止める**(推測で埋めない)
3. 検証: **1,741件すべてに厚年の事務所が1つだけ、国年の事務所が1つだけ**付くこと。0件・2件以上は必ず原因を見る(横浜南のように厚年が空の事務所があるのは正常。市区町村側が空になるのは異常)。

## §5 期待する件数(スクレイパーの検算に使う)
- 街角の年金相談センター: **80**(全国社会保険労務士会連合会 `https://www.shakaihokenroumushi.jp/consult/tabid/218/Default.aspx` の「全国の街角の年金相談センター（80ヶ所）」)。機構側の合計と一致しなければ、どちらかの一覧が古い。**両方の名簿を突き合わせて差分を報告する**
- 年金事務所: 全国で **300件強**(機構の公表では312前後)。都道府県ページの表の件数の合計と、管轄表の行数の合計が一致すること。東京は都道府県ページと管轄表で件数が違って見えた(概略の読み取りで23〜28)。スクレイパーで確定させ、違えば原因を書く
- 都道府県: 47 すべてに最低1件の年金事務所

## §6 スクレイパー仕様(Codex が書く)
- 置き場所 `scripts/madoguchi/`。Node で、`fetch` + HTMLパーサ(既存依存に cheerio があればそれ、無ければ `node-html-parser`)。
- **取得した生HTMLを全部保存**する: `docs/verification/madoguchi-source-2026-09-XX/{slug}/{file}.html`。あとから「機構のページにこう書いてあった」と示せるようにする(§5-5 の「言い切らない」の裏付け)。
- 取得間隔は 1秒以上あける。User-Agent にサイト名を入れる。1回で全部取り、失敗したページは再試行せず一覧に出す。
- パースは **CSSクラスではなく見出し・ラベル文字列**で行う(「郵便番号」「電話番号」「交通」など)。機構のテンプレートが変わってもラベルは残りやすい。
- 出力:
  - `data/madoguchi/offices.json`(§3-1 の型)
  - `data/madoguchi/municipalities.json`(§4)
  - `data/madoguchi/index.json`(市区町村コード → {kousei, kokumin})
  - `docs/verification/madoguchi-2026-09-XX/RESULT.md`: 都道府県別件数表(事務所/街角/管轄表の行数)、欠損項目のある事務所、電話・郵便番号の形式不正、未解決の管轄文字列、市区町村の未割当・二重割当、街角80件との突合差分
- 形式検証: 郵便番号 `^\d{3}-\d{4}$`、電話 `^0\d{1,4}-\d{1,4}-\d{4}$`、URL は `https://www.nenkin.go.jp/` で始まる、`checkedOn` は取得日。
- **禁止**: 欠けている項目を他サイトから補わない。推測で埋めない。空欄は空欄のまま出し、RESULT に載せる。

## §7 ツールの文言で守ること
- 住所・電話は「日本年金機構の公表(YYYY-MM-DD 取得)による」と添え、各件から機構ページへリンク(設計書 §5-4, 5-5 のとおり)。
- 街角には「年金証書の再発行・国民年金の加入納付・事業所の手続きは扱っていません」を添える(§2-3)。
- 「提出先を調べる」の結果には、**厚生年金なら厚年管轄の事務所、国民年金なら市区町村窓口(+国年管轄の事務所)**を出し、両者が違う市区町村では「相談と提出で行く場所が違うことがあります」と一言添える。

## §8 年1回の更新(設計書 §5-6)
同じスクレイパーを毎年4月(年度替わりの統廃合の後)と、機構の「年金事務所の統合・移転のお知らせ」が出たときに回す。差分は `offices.json` の git diff で見える。`checkedOn` を全件更新する。
