## §1 なぜ作るか
- **競合はどこも持っていません**(`docs/feature-gap-analysis-2026-09-02.md`)。機構の公式サイトにはありますが、探しにくい。
- 申請する人は**全員がここを通ります**。例外がありません。
- Search Console で「相談 持ち物」が**11〜12位**、「決定通知書 いつ届く」が**5位**。窓口まわりのクエリで、すでに1ページ目の手前まで来ています。
- **`/columns/teishutsusaki-yuusou`(提出先・郵送)はクリック上位3本の1つ**です。この道具は、その記事の問いに道具で答えます。
- 将来の社労士掲載と**データ構造が同じ**(地域 × 一覧 × 詳細)。先に作っておけば土台が使い回せます。

## §2 3つの機能
1. **提出先の判定** — 障害基礎年金だけなら市区町村、障害厚生年金なら年金事務所。ここを間違えて出し直しになる人がいます。
2. **管轄の窓口を出す** — 都道府県 → 市区町村 で、年金事務所と街角の年金相談センターを表示。
3. **相談の準備** — 予約のしかた、持ち物、聞くことを1枚に。

## §3 提出先の判定ロジック
```
Q1 初診日に入っていた制度: 国民年金 / 厚生年金 / わからない
Q2 初診日は20歳より前か:  20歳前 / 20歳以降 / わからない

国民年金 or 20歳前  → 障害基礎年金のみ → 提出先は【お住まいの市区町村の国民年金の窓口】
                       ※ 第3号被保険者だった期間に初診日がある場合は【年金事務所】
厚生年金             → 障害厚生年金    → 提出先は【年金事務所】
わからない           → 両方を出し、「年金事務所で聞けば、どちらかを教えてもらえます」
```
**断定を避ける文言を必ず添える**:「初診日にどの制度に加入していたかで決まります。分からないときは年金事務所で記録を見てもらえます。」

## §4 予約の情報(2026-09-02 に機構の公式ページで確認済み。実装時に再確認すること)

## §5 窓口データの作り方(ここが実装の大半)
機構は**CSVやExcelを公開していません。**都道府県別のページから作ります。

1. `https://www.nenkin.go.jp/section/soudan/` の都道府県別ページを起点に、各事務所ページを取得。
2. 1件あたり次を取る:
```ts
type Office = {
  id: string; pref: string;
  kind: 'nenkin' | 'machikado';       // 年金事務所 / 街角の年金相談センター
  name: string; zip: string; addr: string;
  tel: string; telNote?: string;      // 音声案内の番号など
  access?: string;                    // 最寄駅からの案内
  jurisdiction: string[];             // 管轄する市区町村(年金事務所のみ)
  url: string;                        // 機構の該当ページ
  checkedOn: string;                  // 取得日 YYYY-MM-DD
};
```
3. `data/madoguchi/offices.json` に置き、**市区町村名 → 事務所id の逆引き索引**も作る。政令市は区まで。
4. **ページに「◯年◯月◯日時点の情報です」と取得日を表示**し、各件から機構の公式ページへリンクする。
5. **住所・電話を自サイトの本文として言い切らない。**「機構の公表による」旨を添える。統廃合があるため。
6. 年1回、更新の仕組みを `docs/prelaunch-checklist-2026-09-02.md` §F の定期作業に追加する。

## §6 画面
```
/dougu/madoguchi
├─ 提出先を調べる      … §3。2問。結果は大きく1行で
├─ 窓口を探す          … 都道府県を選ぶ → 市区町村を選ぶ → 該当の窓口カード
│                        カード: 名称 / 住所 / 電話 / 最寄駅 / 地図を開く / 機構の公式ページ
│                        年金事務所と街角の年金相談センターは分けて表示
├─ 予約のしかた        … §4 の表。電話番号は tel: リンク
├─ 行く日の持ち物      … /dougu/shorui の持ち物と同じ内容を共有(1か所で管理)
└─ 窓口で聞くこと      … /dougu/shorui と同じリスト
```
- 「地図を開く」は Google マップの検索URLへ。**住所を勝手に埋め込み地図にしない**(外部リソースを増やさない)。
- **印刷でA4 1枚**。行く窓口・住所・電話・予約番号・持ち物・聞くことが1枚に載る。
- 選んだ市区町村は localStorage に保存(次回すぐ出る)。「共用のパソコン」なら保存しない。

## 執筆メモ(サイトに載せない)
- 提出先の判定を先頭に置いたのは、`/columns/teishutsusaki-yuusou` がクリック上位3本の1つだから。すでに需要が実測できている問いに、道具で答える。
- 予約番号を大きく出すのは、「予約が要ると知らずに行って何時間も待った」という話がこの領域で多いため。ナビダイヤルは通話料がかかるので、一般電話の番号も必ず併記する(体調が悪い人にとって通話料は小さくない)。
- 地図を埋め込まないのは、外部リソースを増やすとページが重くなるのと、地図SDKが利用者の位置情報に触れうるため。検索URLへのリンクで足りる。
- 社労士事務所をここに出さないのは、いま出すと「窓口を探しに来た人に営業した」形になるから。掲載を始めるときは、この画面の構造をそのまま流用できる。
