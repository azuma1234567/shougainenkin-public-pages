## §2 3つの機能
1. **提出先の判定** — 障害基礎年金だけなら市区町村、障害厚生年金なら年金事務所。ここを間違えて出し直しになる人がいます。
2. **管轄の窓口を出す** — 都道府県 → 市区町村 で、年金事務所と街角の年金相談センターを表示。
3. **相談の準備** — 予約のしかた、持ち物、聞くことを1枚に。

## §3 提出先の判定ロジック

> **2026-09-03 に画面から外した。** 制度と20歳前の2問は聞かない。
> 本人が確実に知っているのは住所なので、そこから入り、厚年・国年の両方の事務所を並べて出す。
> 提出先は、事務所カードの下の**1行**で説明する(質問して分岐するより、両方を並べるほうが間違えない)。
> 　「国民年金だけの請求(障害基礎年金)は、お住まいの市区町村の国民年金の窓口にも出せます。20歳前に初診日がある方も同じです。
> 　　初診日が第3号被保険者(会社員の配偶者)の期間にある方は年金事務所へ。」
> 正は `docs/shorui-madoguchi-redesign-2026-09-03-instructions.md` の B-2・B-3。
> 下の判定表は記録として残す。`lib/madoguchi.ts` の `submission()` も残してあるが、画面からは呼んでいない。
> §3-2 の「制度で出し分ける」は生きている(厚年と国年で事務所が違う市区町村では2枚並べて注意書きを添える)。

```
Q1 初診日に入っていた制度: 国民年金 / 厚生年金 / わからない
Q2 初診日は20歳より前か:  20歳前 / 20歳以降 / わからない

国民年金 or 20歳前  → 障害基礎年金のみ → 提出先は【お住まいの市区町村の国民年金の窓口】
                       ※ 第3号被保険者だった期間に初診日がある場合は【年金事務所】
厚生年金             → 障害厚生年金    → 提出先は【年金事務所】
わからない           → 両方を出し、「年金事務所で聞けば、どちらかを教えてもらえます」
```
**断定を避ける文言を必ず添える**:「初診日にどの制度に加入していたかで決まります。分からないときは年金事務所で記録を見てもらえます。」

### 3-2 判定と、「窓口を探す」で出す事務所の対応(2026-09-03 追記)
**管轄は「健康保険・厚生年金保険」と「国民年金」で別の事務所になることがある。**制度で出し分けないと行き先を間違える。

| 判定 | 提出先 | 「窓口を探す」で出す事務所 |
|---|---|---|
| 厚生年金 → 障害厚生年金 | 年金事務所 | **`jurisdictionKousei` にその市区町村が入っている事務所** |
| 国民年金 / 20歳前 → 障害基礎年金 | お住まいの市区町村の国民年金窓口(第3号被保険者だった期間に初診日があるなら年金事務所) | 市区町村窓口を案内しつつ、相談先として **`jurisdictionKokumin` の事務所** |
| わからない | 両方 | 両方の事務所(同じなら1件) |

実例(`docs/madoguchi-research-2026-09-03.md` §2-4):
- 横浜市南区 … 厚年=横浜中 / 国年=横浜南
- 杉並区 … 厚年=新宿 / 国年=杉並
- 横浜南年金事務所は**厚年の管轄が空**(国年だけを持つ)。事務所側が空になるのは正常。

**厚年と国年で事務所が違う市区町村では、「相談と提出で行く場所が違うことがあります」を必ず添える。**

## §5 窓口データの作り方(ここが実装の大半)
機構は**CSVやExcelを公開していません。**都道府県別のページから作ります。
2026-09-03 の下調べ(`docs/madoguchi-research-2026-09-03.md`)で構造を確認済み。以下はその結果を反映したもの。

1. **3種類のページ**から作る。都道府県ページ(一覧)→ 事務所ページ(住所・電話)→ **管轄区域ページ(市区町村との対応)**。
   **管轄は事務所ページには無い。**管轄区域ページ `.../section/soudan/kankatsu/kankatsu_{slug}.html` から取る。
   - 入口は `https://www.nenkin.go.jp/section/soudan/index.html`(末尾スラッシュだけだとリダイレクトが回る)
   - slug は47個。**新潟は `nigata`**(niigata ではない)
   - 街角のURLは規則が揺れる。**URLを推測せず、都道府県ページの表のリンクを辿る**
2. 1件あたり次を取る:
```ts
type Office = {
  id: string; pref: string;               // pref は slug(tokyo)。表示名は別表
  kind: 'nenkin' | 'machikado';           // 年金事務所 / 街角の年金相談センター
  sub?: 'center' | 'office';              // 街角のみ(センター / オフィス)
  name: string;                           // 機構の表記のまま(読み付き)
  nameShort: string;                      // 読みと「年金事務所」を落とした呼称。管轄表との突合キー
  zip: string; addr: string;
  tel: string; telNote?: string; fax?: string;
  hours?: { weekday: string; weekStartExt?: string; secondSat?: string; closed: string };
  access?: string; parking?: string;
  jurisdictionKousei: string[];           // 健康保険・厚生年金保険(年金事務所のみ。空あり)
  jurisdictionKokumin: string[];          // 国民年金(年金事務所のみ)
  url: string;                            // 機構の該当ページ
  checkedOn: string;                      // 取得日 YYYY-MM-DD
};
```
   **`jurisdiction` の1本では足りない。**管轄は健保・厚年と国年で別の事務所になることがある(§3-2)。**2本に分ける。**
   ねんきんダイヤル・予約受付専用・加入者ダイヤル等の**共通番号は全事務所で同じなので1件ごとに保存しない。**
   `data/madoguchi/common.ts` の定数に置く。
3. `data/madoguchi/offices.json` に置き、**逆引き索引は制度ごとに2本**作る。政令市は区まで。
```ts
// data/madoguchi/index.json
byMunicipality: { [code: string]: { kousei: officeId | null; kokumin: officeId | null } }
```
   キーは**総務省の全国地方公共団体コード**(下の 3.5)。市区町村名ではなくコードを使う。
3.5 **市区町村の選択肢は、機構の管轄表から作らず、総務省の「全国地方公共団体コード」を正にする。**
   管轄表は「西多摩郡」「大島支庁管内」「相模原市」(区なし)のような粒度で書かれていて、
   そのままでは利用者が自分の町村名で探せない。
   - 出典 `https://www.soumu.go.jp/denshijiti/code.html` の最新Excelから **都道府県 + 市区町村 1,898件**
     を `data/madoguchi/municipalities.json` に落とす。
     列: `code, pref, name, kind('市'|'区'|'町'|'村'|'特別区'), city?(政令市名), hoppo?`
     ※ 1,898 = コード表の1,747件 − 政令市20 + その区171。総務省が言う「1,741市区町村」は、
     コード表の1,747件から**北方領土の6村**を除き、政令市を1件と数えた値。この道具は管轄が区ごとに
     違うので**区まで展開**する。北方領土の6村は年金事務所が付かないので、選択肢から除く(`hoppo: true`)。
   - **郡名は総務省のコード表に入っていない**(町村名だけ)。郡は日本郵便の郵便番号データ
     `KEN_ALL`(`https://www.post.japanpost.jp/service/search/zipcode/download/kogaki-zip.html`)で展開する。
     KEN_ALL は市区町村名が「石狩郡当別町」のように郡込みなので、そこから
     「都道府県 + 郡 → 町村(団体コードつき)」を `data/madoguchi/gun-map.json` に作る。
     同名の郡が複数県にあるので**キーは都道府県 + 郡**。取得日と sha256 を持つ。
     生ファイルは生HTMLと同じく `.gitignore`。
   - 管轄表の各エントリを、この1,741件へ展開する:
     「◯◯市」「◯◯区」(特別区)→ そのコード /
     政令市の「◯◯区」(市名なし)→ **その事務所の住所の市**、または脚注(※)の市で特定。**脚注は必ず読む** /
     「◯◯郡」→ その郡に属する町村すべて /
     「◯◯支庁管内」(東京都の島しょ)→ 手書きの対応表 `scripts/madoguchi/manual-map.json` で町村に展開。
     **KEN_ALL でも郡にならないものだけ**をここに残す
     「◯◯郡(△△年金事務所管内の地域を除く。)」→ その郡の町村から、他の事務所が名指ししたものを引いた残り。
     名指しを全部つけてから引き算する(二段階)
   - **展開できなかった文字列は `unresolved.json` に落として止める。推測で埋めない。**
   - 検証: **1,892件(1,898 − 北方領土6村)すべてが、次のどちらかであること。**
     (a) 厚年の事務所が1つ、国年の事務所が1つ
     (b) `split: true` かつ配列2件かつ `splitText` あり — 機構が**市区町村より細かい単位(大字)**で
         2つの事務所に振り分けている市区。該当は15市区(水戸市・宇都宮市・金沢市・浜松市中央区・
         浜松市浜名区・大阪市北区・和歌山市・岡山市北区・岡山市南区・倉敷市・徳島市・松山市・
         西条市・鹿児島市・那覇市)。いずれも厚年だけが分かれる
     これ以外の二重割当は異常。事務所側の管轄が空になるのは正常(横浜南)。**市区町村側が空になるのは異常。**
   - `index.json` の該当エントリは `kousei`/`kokumin` を**配列(2件)**にし、`split: true` と、
     機構の管轄表に書かれた振り分けの文(大字の列挙)を `splitText` に**生のまま**持つ。
     画面では両方の事務所を出し、`splitText` の先頭を「…ほか」で見せて機構の管轄区域ページへリンクし、
     「この市は町名によって事務所が分かれます。機構の管轄区域表で確認してください」を添える。
     **町名で絞り込む機能は作らない。**
4. **ページに「◯年◯月◯日時点の情報です」と取得日を表示**し、各件から機構の公式ページへリンクする。
5. **住所・電話を自サイトの本文として言い切らない。**「日本年金機構の公表(取得日)による」旨を添える。統廃合があるため。
6. 年1回、更新の仕組みを `docs/prelaunch-checklist-2026-09-02.md` §F の定期作業に追加する。
7. 取得の作法とスクレイパー仕様は `docs/madoguchi-research-2026-09-03.md` §6 に従う
   (生HTMLを全部保存 / 1秒以上あける / ラベル文字列でパース / 他サイトから補わない)。
