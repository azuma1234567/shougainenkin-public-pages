## §0.5 参照モック(見た目の正)

`docs/site-mock-2026-09-02-tools/Moushitatesho.html` を**そのまま見た目の正**として使ってください。ブラウザで開くと最後まで操作できます。

## §1 なぜ作るか、なぜここに作るか

Search Console の実測(`docs/metrics/baseline-2026-09-02.md`)で、**このサイトのクリックの47%が `/columns/moushitatesho-a4-insatsu` 1本**に集中している。上位2本で67%。**いま人が来ているのは制度解説ではなく、申立書という実務の詰まり**です。

その記事が答えているのは「A3の様式をA4で印刷するにはどうするか」。**ツールを置けば、その問いに記事ではなく道具で答えられます。**サイト全体で最も価値のある場所に、最も価値のある道具を置く、という判断です。

副次的な効果:
- **指名検索と直接流入を作る。**ゼロクリック検索(この領域はAI Overviews表示率8/8)に耐えるのは、記事ではなく道具です。
- **将来の社労士掲載と相性がいい。**「自分で書いてみて、無理だと分かった人」が、いちばん依頼の意思が固まっています。ツールの出口に相談導線を置ける(v1では置かない。§13)。

## §3 絶対条件(ここを外したら作り直し)

1. **入力内容をサーバーへ送らない。**病歴・症状・氏名・生年月日を扱う。**ネットワーク送信のコードを1行も書かない**(fetch/XMLHttpRequest/sendBeacon/WebSocket、外部フォーム、外部フォント以外の外部リソース)。保存先はブラウザの中だけ。
2. **アカウント登録なし、ログインなし、課金なし。**
3. **既存47記事のURL・slug・h1・本文を変更しない。**
4. **判定をしない。**「これなら通ります」「2級相当です」の類を一切出さない。ツールは書式を整えるだけで、内容の良し悪しを評価しない。
5. **AIを使わない。**下書き生成、要約、添削のいずれも入れない。
6. **文章を勝手に書き換えない。**入力された文章は、印刷まで一字一句そのまま運ぶ。整形は改行と字送りだけ。
7. **計測に本文を含めない。**§13の通り、送るのは操作の有無だけ。

## §5 画面の流れ

1画面に1つのことだけを置く。**申立書を書く日は、それだけで一日ぶんの作業**になる人がいる(`/columns/shinsei-shindoi`)。急かさない。

```
/tsukuru/moushitatesho
├─ 0. はじめに      … 何ができるか / 保存はこの端末の中だけ / 途中でやめて戻れる
├─ 1. 基本          … 傷病名・発病日・初診日・生年月日
├─ 2. 請求のかた    … 本来請求 / 事後重症 / 遡及(裏面のどちらを書くかが決まる。§6-2)
├─ 3. 期間          … 枠の追加・並べ替え・削除。区切りの支援(§6)
├─ 4. 裏面(認定日頃) … 請求のかたによって出す/出さない
├─ 5. 裏面(現在)     … 同上
├─ 6. 日常生活状況   … 10項目 × 1〜4
├─ 7. その他・手帳   … 自由記述・手帳の交付状況
└─ 8. 印刷          … /tsukuru/moushitatesho/insatsu へ
```

共通仕様:
- 上部に**進み具合のバー**を置く。ただし**「あと◯%」「残り◯項目」は出さない**(急かす表示にしない)。現在地だけを示す。
- 全画面に「**ここまでの内容は自動で保存されています**」を常時表示。
- どのステップからでも自由に行き来できる。**未入力のまま次へ進める**(必須で止めない。空欄のまま印刷して手書きで足す人がいる)。
- 「**中断する**」ボタンを各画面に置き、押すとトップへ戻る。責める文言を出さない。

## §6 期間の区切り(このツールの中心)

### 6-1. 区切りの支援
公式の記載要領は「**3〜5年の間で区切る**」「発病から現在まで、期間をあけずに」「**受診の有無で分ける**」。これをツールが機械的に助ける。

枠を編集している間、常に次を出す(**警告ではなく、気づきとして**。赤字・エラー色は使わない):

| 検知 | 出す文言 |
|---|---|
| 前の枠の `to` と次の枠の `from` が連続していない | 「◯年◯月から◯年◯月までが、どの枠にも入っていません」 |
| 1つの枠が5年を超える | 「この枠は◯年◯か月あります。3〜5年で区切るのが公式の案内です」 |
| 枠が時系列に並んでいない | 「日付順に並べ替えますか」(ワンクリックで並べ替え。**勝手に並べ替えない**) |
| 最初の枠の `from` が発病日より後 | 「発病(◯年◯月)から最初の枠までが空いています」 |
| 最後の枠の `to` が現在より前 | 「◯年◯月から今日までが、どの枠にも入っていません」 |
| `jushin: true` なのに医療機関名が空 | 「受診した期間なので、医療機関名の欄があります」 |

**どれも入力を妨げない。**保存も印刷もできる。

### 6-2. 請求のかたと裏面の対応
| 請求のかた | 裏面 上欄(障害認定日頃) | 裏面 下欄(現在) |
|---|---|---|
| 本来請求(認定日請求) | 記入する | 記入しない |
| 事後重症請求 | 記入しない | 記入する |
| 遡及請求 | 記入する | 記入する |

ステップ2の選択で、4・5のどちらを出すかを切り替える。**印刷では、書かない側の欄も様式どおり空欄で出す**(様式から欄を消さない)。

### 6-3. 続紙
表面に収まる枠の数は、**§10 で公式様式から確定する**(目分量で決めない)。それを超えたぶんは自動で続紙に送る。

- 続紙の右上「No」欄に**通し番号**を入れる(1枚目の続紙が「1」)。
- 画面には「◯枚目の続紙に入ります」と出す。**枚数の上限を設けない。**
- 続紙にも表面・裏面がある。裏面が空の続紙は印刷しない。

## §7 はみ出し検知(実装のいちばん難しいところ)

紙の枠は固定サイズ。**入力欄では収まって見えたのに、印刷すると本文が枠から溢れる**——これが起きると、この道具は信用を失う。

### やること
1. 各テキスト欄に対して、**印刷時と同じ紙面幅・同じフォント・同じ字送り**で描画した測定用のDOMを画面外に持つ(`position:absolute; visibility:hidden`)。フォントは印刷CSSと**同一のものを同一の指定で**使う。
2. 入力のたびに測定用DOMの `scrollHeight` を測り、枠の高さと比べる。
3. 状態は3つ。**文字数ではなく、実測の高さで判定する**(全角・半角・改行で結果が変わるため)。

| 状態 | 表示 |
|---|---|
| 収まる | 何も出さない |
| 残りわずか(枠の85%超) | 「この枠はあと2行ほどで埋まります」 |
| はみ出す | 「この枠に収まりません。**続紙へ送る**か、期間を分けると収まります」+ その場のボタン |

4. **勝手に切り詰めない。勝手に縮小しない。**溢れたまま印刷させない代わりに、選択肢を出す。
5. フォントの読み込み完了(`document.fonts.ready`)を待ってから初回測定する。待たずに測ると全部ずれる。

### テスト
- 全角100字・改行20回・半角英数のみ・URL貼り付け・絵文字混在の5パターンで、**画面の判定と実際の印刷結果が一致すること**をスクリーンショットで確認する。

## §8 印刷設計

### 8-1. 出す紙は2種類(B4は作らない)

| 名前 | 中身 | 使う人 |
|---|---|---|
| **A3見開き** | 公式様式と同じ原寸。表面1枚・裏面1枚 | コンビニでA3を等倍印刷する人 |
| **A4分割** | A3の紙面を左右で2分割し、A4×2枚に。表裏で計4枚 | 自宅のプリンターの人(**こちらを既定にする**) |

`/columns/moushitatesho-a4-insatsu` の記述と揃える:
- 原本はA3。
- A4に分けて印刷したものでも受け付けられるのが実務上の扱いだが、**提出前に年金事務所へ確認するよう案内する**(断定しない)。
- A3で印刷するときは「**用紙に合わせる」ではなく倍率100%(等倍)**。この注意を印刷画面に必ず出す。

### 8-2. 実装方法
**サーバー不要。ブラウザの印刷機能をそのまま使う。**PDF生成ライブラリを入れない(PDFが要る人はOSの「PDFに保存」を使う)。

```css
@page { size: A4 portrait; margin: 0; }      /* A4分割のとき */
@page { size: A3 portrait; margin: 0; }      /* A3見開きのとき */
@media print {
  html, body { margin: 0; }
  .sheet { page-break-after: always; }
  .no-print { display: none !important; }
}
```

- 紙面は **mm 指定**で組む(px で組むと拡大率でずれる)。ルート要素に実寸を与え、中身は mm 基準。
- **ブラウザのヘッダー・フッター(URL・日付・ページ番号)を消すよう、印刷画面で案内する。**CSSでは消せない。「その他の設定 → ヘッダーとフッターのチェックを外す」を、Chrome/Safari/Edge それぞれの文言で書く。
- 印刷プレビュー画面に、**紙面をそのまま縮小した画像的プレビュー**を出す(実際の `.sheet` を `transform: scale()` したもの。別に作らない。作ると必ず食い違う)。

### 8-3. 紙面の組み立て
アプリの `buildMouHTML`(`src/MockupV4App 14.tsx` の `/* --- 病歴・就労状況等申立書 --- */` 以降)が**唯一の参考実装**。ただしそのまま移植しない。理由は次の2つ。

1. **アプリの紙面は「様式第120号の4」と印字しているが、これは誤り。**様式第120号の4 は **診断書(精神の障害用)** の様式番号です。申立書のヘッダーは §10 で公式ファイルから転記すること。**アプリの表記をコピーしないこと。**(アプリ側にもこの誤りを直す課題があることを報告に含めてください)
2. アプリの紙面は表の幅を%で置いており、公式様式の実寸と一致していない。§10 で測った値に置き換える。

参考にしてよいのは、**日付の書き方(`ymd`/`ym`)、チェックの書き方(`■`/`□`)、1〜4の丸囲み、HTMLエスケープの方針**です。

## §9 下書きの保存・持ち出し

| 機能 | 仕様 |
|---|---|
| 自動保存 | 入力のたびに `localStorage`(キー `shougainenkin-note:moushitatesho:v1`)。debounce 500ms |
| 保存しない選択 | 「**共用のパソコンを使っている**」チェック。オンの間は保存せず、タブを閉じると消える。初回に必ず選ばせる |
| 書き出し | `.json` でダウンロード。ファイル名 `moushitatesho-YYYY-MM-DD.json` |
| 読み込み | `.json` を選ぶと復元。`version` が違えば読み込まず、その旨を出す |
| 消す | 「この端末から消す」ボタン。**2段階確認**。消したら戻せないことを明記 |

- `localStorage` は使えないことがある(プライベートウィンドウ、サイトデータのブロック)。**読み書きは必ず try/catch で囲み、失敗しても入力は続けられる**ようにする。失敗したら「この端末には保存できない設定になっています。書き出しを使ってください」と出す。
- 印刷画面に**「控えを取ってください」**を出す。更新のときに前回の内容を見られることが効くため(`/columns/` の複数記事で扱っている)。

## §10 様式の寸法を測る(飛ばさないこと)

**目分量でレイアウトを作らない。**公式ファイルから測る。

1. 日本年金機構の「病歴・就労状況等申立書を提出するとき」ページから、**PDFとExcelの両方**を取得する。
   `https://www.nenkin.go.jp/shinsei/jukyu/shougai/shindansho/20140516.html`
   本体(表面・裏面)と**続紙**の両方。
2. `pdfinfo` でページサイズを確認する。**A3かB4かを実測で確定**し、結果を報告する(記事では「原本はA3」としているので、違っていたら記事の訂正も必要)。
   ```
   pdfinfo 病歴・就労状況等申立書.pdf   # Page size を見る
   ```
3. `pdftotext -layout` で全文を抜き、**画面と紙面に出す固定文言をすべて転記**する。とくに:
   - ヘッダー(表題・様式番号の有無・かっこ書き)
   - 各欄の見出し語
   - 日常生活状況の**10項目の文言と並び**
   - 1〜4の選択肢の**文言**
   - 働いていない理由の**ア〜オの文言と並び**
   - 記入上の注意書き
   - 署名欄まわりの文言
   §4 の定数と**1字ずつ突き合わせ、違いがあればすべて報告**する。
4. 各欄の位置と大きさを mm で測る。`tools/pdf-coordinate-picker.html`(アプリrepo)が使える。測った値は `data/moushitatesho/layout.ts` に**mm の定数**として置き、CSSはそこから生成する。数値をコンポーネントに直書きしない。
5. 公式PDFと、このツールの印刷結果を**重ねて比較**する(片方を50%の透明度で重ねたスクリーンショット)。ずれが 1mm を超える欄があれば直す。

## §11 出してはいけないもの・言ってはいけないこと

- 「この内容なら受給できます」「◯級相当です」など、**結果の予測**
- 「必ず通る書き方」「審査に有利な表現」など、**攻略の示唆**
- 入力内容に対する**評価・添削・言い換えの提案**
- 「重く書きましょう」の類。逆に「盛らないでください」も書かない(**内容に踏み込まない**)
- 特定の社会保険労務士・事務所への誘導(v1では相談導線そのものを置かない)
- 記入例として**実在しそうな他人の病歴**を出すこと。例を出すなら、様式の使い方が分かる最小限の記法だけ

出してよい注意書きは、**公式の記載要領に書いてあることの引き写しだけ**。出典を添える。

## §12 アクセシビリティ・体調への配慮

- **1画面1トピック。**スクロールの長い画面を作らない。
- 文字サイズはブラウザ設定に追随(`rem`)。**16px 未満を使わない。**
- モバイル375pxで横スクロールが出ないこと。テキスト入力欄は**縦に伸びる**(内側スクロールにしない。書いたものが見えなくなるため)。
- **フォーカスの見た目を消さない。**キーボードだけで全ステップを完了できること。
- 色だけで状態を伝えない(はみ出し検知も文言で伝える)。
- 自動保存の通知は**うるさくしない**(常時の静かな1行。トーストを毎回出さない)。
- ダークモードに追随する。ただし**印刷は常に白地・黒文字**。

## 執筆メモ(サイトに載せない)
- 置き場所を `/tsukuru/` にしたのは、将来ここに道具が増えるため(整合性チェック、期間の組み立て、控えの管理)。`/tools/` にしなかったのは、既存IAが全部ひらがな動詞だから。
- いちばん技術的に難しいのは §7 のはみ出し検知。ここを「文字数で判定」で済ませると必ず破綻する(全角・改行・半角で高さが変わる)。印刷と同じ条件で実測する以外に方法はない。
- §10 を強く書いたのは、この種のツールが失敗する原因のほとんどが「様式を目分量で作った」だから。1mmずれた紙は、窓口で差し戻される可能性がある。
- アプリの「様式第120号の4」は診断書(精神)の様式番号で、申立書のものではない。アプリ側も直す必要がある。これは今回の調査で見つかった既存の不具合。
- 相談導線をv1に置かなかったのは、道具として信用される前に売り込むと、道具そのものが疑われるため。データを見てからでいい。
- 計測から本文を外したのは当然として、「文字数」すら送らない。文字数は病歴の重さの代理変数になりうる。
