## §1 なぜ作るか

申請を**始めたばかりの人、これから考える人**にとって、いちばん知りたいのに、いちばん誰も答えてくれないのが「自分はどのくらいの位置にいるのか」です。社労士は依頼前に断定を避け、医師は等級の話をしない。結果、当事者は「やってみないと分からない」とだけ言われて止まります。

**ところが、国は答えの半分を公表しています。**「精神の障害に係る等級判定ガイドライン」(平成28年9月)には、**障害等級の目安表**が載っています。日常生活能力の判定(7項目)の平均と、日常生活能力の程度(5段階)の組み合わせで、目安の等級が決まる表です。

このツールがやるのは、**その公表物を、当事者が読める形にすること**だけです。判定しているのは国であって、このサイトではありません。ここが全ての設計の起点です。

戦略上の位置づけ:
- **この領域はAI Overviews表示率8/8**(`docs/metrics/ai-baseline-2026-09-02.md`)。記事では読まれずに終わる。道具なら来る理由になります。
- 申請前の人が最初に触る道具になれば、**そこから申立書ツール(`docs/moushitatesho-tool-design-2026-09-02.md`)へ流れます。**申請の入口と出口が1つのサイトの中でつながります。
- 「国の基準をそのまま見せる」ことは、審査への不信が強いこの領域で、**もっとも信用が積み上がる振る舞い**です。

## §3 絶対条件

1. **判定しない。**主語は常に「国のガイドラインでは〜とされています」。「あなたは2級です」「2級相当です」と書かない。
2. **確率・可能性の断定をしない。**「通る可能性は◯%」「◯割が受給」を出さない。数字を出してよいのは**判定平均の計算値**と、**§10 の出典つき統計を、確率としてではなく分布として示す場合**だけ。
3. **予測の語彙を使わない。**「通りそう」「もらえそう」「難しそう」「厳しい」を書かない。
4. **入力と結果をサーバーへ送らない。**`fetch` / `XMLHttpRequest` / `sendBeacon` / `WebSocket` を書かない。
5. **AIを使わない。**固定ロジックのみ。
6. **目安表を1セルも改変しない。**空欄も空欄のまま扱う(§5)。
7. **総合評価の要素は、ガイドライン本文の引用でのみ語る。**言い換えて強めたり弱めたりしない。
8. **対象外の障害を対象のように扱わない。**このガイドラインは精神障害・知的障害・発達障害のみが対象(§4-0)。

## §4 画面の流れ

### 4-0. 入口のふるい分け(最初にやる)

```
Q. どの障害で請求を考えていますか
  ├ 精神の障害(うつ病・双極性障害・統合失調症・不安障害 など) → 精神障害モード
  ├ 知的障害                                                  → 知的障害モード
  ├ 発達障害(ASD・ADHD など)                                  → 発達障害モード
  └ それ以外(身体・内部疾患・がん・難病 など)                  → 対象外の案内へ
```

**対象外の案内**(専用画面。中途半端に使わせない):
> このガイドラインは、精神の障害(精神障害・知的障害・発達障害)の審査のために国が公表しているものです。ほかの障害には、それぞれ別の認定基準があり、この目安表は使えません。
> → 病気から探す(`/byoki`) / 障害認定基準について(該当コラム)

### 4-1. 2つのモード(**精度がまるで違うので、最初に選ばせる**)

| モード | 誰が使うか | 精度 |
|---|---|---|
| **A. 診断書がもう手元にある** | 診断書を受け取った人、更新の人 | **高い。**医師が実際に書いた欄を転記するので、審査が見るのと同じ値になる |
| **B. まだ診断書がない** | これから請求する人、考えている人 | **参考値。**自分で見立てた値であって、医師が書く値とは別物 |

モードBには、結果画面まで一貫して次を出す(消せない):
> ここで使った数字は、あなたが自分で選んだものです。**審査が見るのは、医師が診断書に書いた数字です。**同じにならないことがあります。この結果は「医師に何を伝えるか」を考える材料として使ってください。

**これがこのツールの誠実さの中心です。**ここを曖昧にすると、当たらない占いになります。

### 4-2. ステップ

```
/dougu/mitate
├─ 0. はじめに        … 何をする道具か / 判定しないこと / 端末内で完結すること
├─ 1. 障害の種類      … §4-0
├─ 2. モード          … §4-1
├─ 3. 判定(7項目)     … 1問1画面。4択
├─ 4. 程度(5段階)     … 1画面
├─ 5. 総合評価の質問  … §7。障害の種類で出る質問が変わる
└─ 6. 結果            … §8
```

- 3〜5は**すべて任意**。答えた範囲で結果を出す(7項目のうち1つでも答えれば平均は出る)。
- 「答えたくない」を各問に置く。飛ばした項目は平均の計算に入れない。
- 3の設問文の上に常時: 「**ひとり暮らしかどうかにかかわらず、『援助がなかったらどうか』で考える**のが、国の定めた見方です。」

### 5-3. 照合の手順(必ず実行)
原本PDFのテキスト抽出は**空欄セルが落ちて行の値が左へ詰まります。**これが原因で、アプリの初版も「2.5以上3.0未満」以下の行がずれていました。**抽出結果をそのまま信じないこと。**

1. 原本を取得: `https://www.mhlw.go.jp/file/04-Houdouhappyou-12512000-Nenkinkyoku-Jigyoukanrika/0000130045.pdf`(表1は PDF 7ページ目 / 紙面 -5-)
2. PyMuPDF 等で**語の x 座標**を取り、列の中心に割り当てる。アプリで確認済みの列中心: **(5)=172.6 / (4)=253.9 / (3)=335.2 / (2)=416.6 / (1)=497.9**
3. §5-2 の表と全セル一致することを確認し、**結果を報告**する。1セルでも違えば実装を止めて報告すること。

### 5-4. 空欄の扱い
空欄は「情報がない」ではなく、**「判定と程度の整合性が低い」**という意味を持ちます。ガイドライン第3-3-(1)-① は、その場合に診断書作成医への内容確認等を求めています。結果画面では次のように出す(断定しない):

> 国のガイドラインの表では、この組み合わせに目安が定められていません。判定(7項目)と程度の間に開きがあるためです。ガイドラインは、こうした場合は診断書を書いた医師に内容を確認したうえで、ほかの記載も含めて総合的に評価する、としています。

### 5-5. 境界の扱い
境界値(1.5 / 2.0 / 2.5 / 3.0 / 3.5)は**「以上」の側=上の行**に入る。平均は**小数第2位で丸めてから**表に当てはめる(表示した数値で読者が検算できるように)。

### 5-6. 制度による違い(結果画面に必ず出す)
表1《表の見方》3 の注記:
> 表の中の「3級」は、**障害基礎年金として認定する場合には「2級非該当」と置き換える**ことになっています。障害基礎年金には3級がないためです。初診日にどの制度に加入していたかで、扱いが変わります。

初診日の制度(国民年金/厚生年金/不明)を任意で1問聞き、**国民年金を選んだ場合は結果の「3級」表記を「2級非該当(3級のない制度のため)」と併記**する。**書き換えるのではなく併記**する(表の原型を壊さない)。

## §7 総合評価レイヤー(ここが「精度高め」の実体)

目安表だけでは粗いままです。**ガイドライン第3「総合評価」には、「1級または2級の可能性を検討」「2級の可能性を検討」と明記された具体例が並んでいます。**これを質問に変換し、当てはまったものを**原文の引用つき**で見せます。

### 7-1. 設計原則
- **すべて出典つきの引用で語る。**要約して強めない。引用のあとに1行だけ平易な言い換えを添えてよい。
- **点数化しない。等級を計算し直さない。**「目安はこう、ただしガイドラインはこういう場合を挙げている」と**並べて置くだけ**。
- 当てはまった項目は「**動きうる方向**」を示す(上げる方向 / 下げる方向 / 整合性)。矢印や色で煽らない。
- 該当した項目は**最大6件**まで。多いと読まれない。

### 7-2. 質問と、対応するガイドラインの記述

**共通(全モード)**

| 質問 | 該当したとき出す引用(要旨) | 方向 |
|---|---|---|
| 就労継続支援A型・B型、就労移行支援、障害者雇用制度を利用して働いている | 「就労系障害福祉サービス(就労継続支援A型、就労継続支援B型)及び障害者雇用制度による就労については、1級または2級の可能性を検討する。就労移行支援についても同様」 | 上げる |
| 一般企業だが、障害者雇用と同程度の援助・配慮を受けている | 「障害者雇用制度を利用しない一般企業や自営・家業等で就労している場合でも、就労系障害福祉サービスや障害者雇用制度における支援と同程度の援助を受けて就労している場合は、2級の可能性を検討する」 | 上げる |
| ひとり暮らしだが、家族や福祉サービスの援助を受けている(いまは受けていないが必要な状態も含む) | 「独居であっても、日常的に家族等の援助や福祉サービスを受けることによって生活できている場合(現に受けていなくても、その必要がある状態の場合も含む)は、それらの支援の状況(または必要性)を踏まえて、2級の可能性を検討する」 | 上げる |
| 施設・グループホーム・援助できる家族との同居で、生活が安定している | 「支援が常態化した環境下では日常生活が安定している場合でも、単身で生活するとしたときに必要となる支援の状況を考慮する」 | 上げる |
| 在宅で、家族や重度訪問介護等から**常時**援助を受けている | 「在宅で、家族や重度訪問介護等から常時援助を受けて療養している場合は、1級または2級の可能性を検討する」 | 上げる |
| 入院していて、安全確保のために常時個別の援助が必要 | 「病棟内で、本人の安全確保などのために、常時個別の援助が継続して必要な場合は、1級の可能性を検討する」 | 上げる |
| 欠勤・早退・遅刻が多い | 「精神障害による出勤状況への影響(頻回の欠勤・早退・遅刻など)を考慮する」 | 上げる |
| 仕事のあと、家では何もできない状態が続く | 「就労の影響により、就労以外の場面での日常生活能力が著しく低下していることが客観的に確認できる場合は、就労の場面及び就労以外の場面の両方の状況を考慮する」 | 上げる |
| 7項目のうち、特定の項目だけが著しく重い(自動判定) | 「『日常生活能力の判定』の平均が低い場合であっても、各障害の特性に応じて特定の項目に著しく偏りがあり、日常生活に大きな支障が生じていると考えられる場合は、その状況を考慮する」 | 上げる |
| 判定と程度に開きがある(自動判定=表が空欄) | 「『日常生活能力の程度』と『日常生活能力の判定』に齟齬があれば、それを考慮する」 | 整合性 |

## 執筆メモ(サイトに載せない)
- この道具の唯一の正当性は「国が公表しているものを、そのまま見せている」ことにある。1セルでも表を間違えたら、その正当性が消えて、ただの当たらない占いになる。§5-3 を必ずやらせる。
- アプリの初版は、PDFのテキスト抽出で空欄セルが落ちて行がずれていた。同じ罠に必ずハマるので、座標照合の手順と列中心の実測値を指示書に書き込んだ。
- 「精度高め」の実体は、目安表そのものではなく §7 の総合評価レイヤー。目安表だけなら他所にもある。**ガイドライン本文の「◯級の可能性を検討する」を、本人の状況に当てて引用で見せる**のは、たぶんどこもやっていない。とくに就労継続支援A型・B型・障害者雇用が「1級または2級の可能性を検討」と明記されている事実は、当事者にほとんど知られていない。
- モードA/Bを分けたのは、この道具がいちばん嘘をつきやすい場所だから。判定と程度を書くのは医師であって本人ではない。ここを曖昧にすると「当たらなかった」という体験だけが残り、サイト全体の信用が落ちる。
- 結果の共有リンクを作らないのは、URLに健康状態が乗るため。SNSに貼れる形にした瞬間に事故が起きる。
- 相談導線を入れなかったのは申立書ツールと同じ理由。ただしこの道具は、将来いちばん社労士掲載と相性がよくなる場所でもある(自分の位置を知って、依頼を決める人が通る)。置くとしても、道具が信用されたあと。
