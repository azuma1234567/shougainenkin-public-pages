# /byoki と /joukyou の一覧ページを刷新する (2026-09-05)

対象: `lib/hub-index.tsx`(`renderHubIndex`)と、その CSS。`/nayami` `/okane` `/erabu` も同じ部品なので、**同時に直る**(それでよい)。
モック: `docs/site-mock-2026-09-05-hubindex/byoki-mock.html`(/byoki を再現。記事数・実例数は仮値)。

## §1 いまの何が悪いか(本番を見て確認した)

1. **カードが縦一列**。`.p-grid` に列数のクラスが無いので 1 列になり、21 枚のカードが約 7 画面ぶん縦に並ぶ。カードの中身は病名と「読む →」だけで、130px の空箱が 21 個。
2. **一覧の前に本文 4 段落**。読者は自分の病名を探しに来ているのに、一覧が 1 画面目に無い。
3. **カードに情報の手がかりが無い**。「がん」「肝臓の病気」と書いてあるだけで、開く前に「自分に関係あるか」「何が書いてあるか」が分からない。離脱の主因。
4. 21 個を 4 群に分けてはいるが、群の見出しが弱く、群ごとの違い(内部疾患は不支給が高い、など)が伝わらない。

## §2 直す形(モックのとおり)

### 上部(1 画面目)
- パンくず / h1 / リード 1 文 / 「最終更新日 · N の病気」。
- **分類チップ**: 群ごとのアンカーリンク(「精神・発達 9」など、件数つき)。
- **絞り込み欄**(/byoki だけ): 病名で絞る。クライアント側だけで動き、**何も送信しない**。文字を入れるとカードが絞られ、0 件なら「見つからないときは [悩みから探す] [はじめての方へ]」を出す。/joukyou ほか(9 件以下)には出さない。

### 一覧
- **3 列グリッド**(1000px 以下は 2 列、640px 以下は 1 列)。
- 群ごとに `h2`(件数つき)と **群の 1 行メモ**(§4)。
- カード = 病名(`h3`)/ **一言**(§3。2 行以内)/ メタ行「記事 N本 · 実例 N件」/ 「読む →」。
  - 記事数 = `hubColumnSlugs(path).length`。実例数 = `jitsureiFilter` を `SAIKETSU_CASES` に当てた件数。**0 のものは出さない**(「記事 0本」を見せない)。両方 0 なら メタ行を空にする。
  - 全カード同じ扱い(目立たせるカードを作らない)。ホバーで枠が primary に。
- カード全体がリンク。中に別リンクを入れない。

### 下部
- 既存 `body` の段落は**一覧の下**に「このページの使い方」として残す(消さない。SEO の本文であり、読む人もいる)。ただし統計の段落(70.3% / 20.6% …)は §4 の群メモに移すので、`body` からはその段落を外す(二重に出さない)。
- `tail` は残す。

### SEO / AIO
- `CollectionPage` + `ItemList`(各ハブを `ListItem` に。`name` = ラベル、`url` = パス)の JSON-LD を出す。パンくずの JSON-LD は既存の `Breadcrumb` が出しているなら重ねない。
- `h2` は群名(「精神・発達」)。カードの `h3` は病名。**見出し階層を崩さない**。
- 絞り込みは JS だが、**JS なしでも全カードが見える**(初期表示は全件)。
