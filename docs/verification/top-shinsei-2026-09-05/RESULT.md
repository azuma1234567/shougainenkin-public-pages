## 入れたもの

### トップ(/)
- ヒーローの数字を、在庫数から**訪問者の判断が変わるもの**に入れ替えた:
  支給に至った割合 **87.0%** / 精神の障害の割合 **70.3%** / 結論が分かれた実例 **91** /
  出典・確認日 **全件**。数字の下に1文「10人のうち7人が精神の診断書で申請しています。」
  数字は黒。値は `lib/stats` と `SAIKETSU_COUNTS` から取り、ページには書いていない。
- `WebSite` の構造化データに `SearchAction`(`/?q={search_term_string}`)を足した。
- **「数字で見る」のセクションは作っていない。** 実例の帯に「数字で見る障害年金 →」を1本足しただけ。
- 「探す」を **「どこから探しますか」** に変え、ブロック名を
  **病気別 / 状況別 / 困りごと別 / お金**(`site-structure` 指示書 §3 と同じ語)にそろえた。
  入口ごとに型を変えた:

| 入口 | 型 |
|---|---|
| 病気別 | チップ 上位10 +「…ほか11」+「21の病気 →」 |
| 状況別 | チップ9つ +「9つの状況 →」 |
| 困りごと別 | 1行リスト5件(左に困りごと、右に小さな数字・黒) |
| お金 | 金額2つを数字の組版で(タイルにしない)+ 1文 |
| 自分でやるか、頼むか | 2枚の小カード + 費用の相場へ |

### /shinsei
- 1000px 以上は**2カラム**。左200pxに固定の目次(番号 + `short`、現在地は
  `IntersectionObserver`、チェックが全部ついたステップは番号が `--c-ok` の ✓、
  上に「進み具合 N/8」と細い棒)。1000px 未満は横に流れるチップ列(sticky)。
- ステップカードを圧縮: `header`(番号 / 見出し + 1文 / 右端にデータ1つ)→ 本文 →
  2列(左「この段階ですること」チェック式 / 右「つまずきやすいところ」`--c-warn` の左罫線)→
  `footer`(道具チップを先頭に、関連記事チップ、右端「次へ」)。**文は削っていない。**
- 右端のデータは検証済みの数字だけ(1 初診日 35件 / 2 納付要件 10件 / 5 診断書 15件 /
  7 標準処理期間 3か月 / 8 支給に至った割合 87.0%)。持たないステップには出さない。
- チェックは `localStorage`(`shougainenkin-note:shinsei-progress:v1`)。**送信しない。**
  1つ以上ついたら「この端末だけに保存されます / リセット」を目次の下に出す。
  JavaScript が無いときは `noscript` の箇条書きで読める。

## §4 の検証

**1. build / 公開前チェック → ○**
```
npm run typecheck / npm run build → エラーなし
node scripts/prelaunch-check.mjs  → ページ数 166 / × は B-1・B-3
```
B-10 は追補で解消済みなので、基準から増えていない。

**2. スクリーンショット → ○**
`top-1400.png` `top-390.png` `shinsei-1400.png` `shinsei-390.png`。

**3. ステップ8枚の合計高さ → ×(33.3%短縮。目標は35%以上)**

| | 合計 | 1枚あたり |
|---|---:|---|
| 変更前(本番・1400px) | 4,709px | 589px(8枚とも) |
| 変更後 | **3,139px** | 387〜414px |

**33.3% 短くなったが、35% には 1.7 ポイント届かなかった。**
1枚あたりは指示書 §2-2-4 の目標(380〜450px)に収まっている。
指示書は「各600〜700px・合計5,000px以上」を前提に35%と置いていたが、実測の変更前は
1枚589px・合計4,709pxだったので、同じ削り幅でも割合が届かない。
これ以上詰めると本文の行間とチェック欄のタップ領域(44px)を削ることになるので、
**直さずに数値を報告する。**

**4. `<p>` `<li>` の集合(前 ⊆ 後) → /shinsei は○、トップは×(16件)**

| ページ | 変更前 | 変更後 | 変更後に無い |
|---|---:|---:|---:|
| / | 89文 | 88文 | 16 |
| /shinsei | 187文 | 189文 | 4(すべて footer のチップの連結の差。文は残っている) |

トップの16件の内訳:
- **6件**: ヒーローの在庫数の1つ「21 病気ごとの審査の見どころ」ほか、チップの連結の差
  (病名チップ群・実例の帯のチップ)。文ではない。
- **10件**: 「困りごと別」の旧カード6枚の見出しと説明文
  (「一度の不支給が最終結論とは限りません。」「閉院・カルテ破棄でも道はあります。」など)。
  指示書 §1-2-5 が、このブロックを**1行リスト**に変えると指定しているため。
  同じ内容は移動先の `/nayami` の各ハブと、リンク先のコラムに残っている。
  使われなくなった `worries` の定義は、そのまま残すと死んだコードになるので消した。
  **本文の文を消す指定なので、ここは報告にとどめる(戻すなら1行リストをやめることになる)。**

**5. チェック → ○**
2つチェック → 再読み込み後も2つ残る。`localStorage` に
`{"step-1:0":true,"step-1:1":true}`。**GET 以外の通信 0件**(Playwright で監視)。
JavaScript を切っても、ステップカード8枚と「この段階ですること」8つが読める。

**6. 数字 → ○**
- ヒーローの 87.0% と 70.3% は `/suuji` の同じ値(`lib/stats` から導出)。
- 「困りごと別」の5つ: 期限 3か月 / 争点 35件 / 争点 15件 / 継続 96.8% / 最大5年。
  件数は `SAIKETSU_CASES`、継続は認定状況調査から。3か月は
  日本年金機構のサービススタンダード(`/columns/shinsei-kikan` に記載)。
- 数字の `color` は computed style で **rgb(20, 66, 94) = `--c-heading`**
  (ヒーロー4つ・金額2つ・困りごとの5つとも)。

**7. `SearchAction` → ○**
構造化データに入っており、`/?q=うつ病` を開くと検索欄に「うつ病」が入る。

**8. 意味の色とタイル行 → ○**
意味の色は `--c-ok` `--c-warn` `--c-danger` の3つのまま。図表の色は追補で登録済みの
`--chart-1`〜`4`。棚卸しは色10・font-size 10・角丸3・影1で基準内。
**トップに「数字で見る」のタイル行は無い**(`suuji-stat-tile` も金額タイルも出ていない)。
