### 報告すべき差分

1. **診断書8種の様式番号は、機構の公式ページに記載が無い。**設計書 §6 は「診断書8種の様式番号」を埋めよと指示しているが、8ページのいずれにも様式番号の記載がなく、様式PDF本体のテキスト層にも無い(診断書PDFは画像主体で、抽出できるのは記入欄のラベルだけ)。**推測で番号を書かず、空欄のままにした。**様式番号を出しているのは年金請求書(107号・104号)だけ。
2. **設計書 §3 の質問4は「内部(心・腎・肝・呼吸器・糖尿)」を1つの選択肢にしているが、公式の診断書は3様式に分かれている**(呼吸器 / 循環器 / 腎・肝・糖尿)。選択肢はモックのまま変えず、内部を選んだときは3様式を並べて出している。
3. **様式のリンクは PDF ではなく公式ページへ張った。**設計書 §6 は「各様式のダウンロードURL(公式へ直リンク)」だが、PDFのファイル名(例 `04-1.pdf`)は改定で変わるため、ページへ張るほうが「古い様式が残る事故を防ぐ」という §6 の目的に合う。自サイトにPDFは置いていない。
4. モックの `url:'#'` はすべて上表の公式ページへ差し替えた。`tool:['申立書をつくる','#']` は `/dougu/moushitatesho` へ。
5. 年金請求書は制度で様式が2つあるため、**書類は1件のまま**、様式の行に該当するものを出す(制度が未回答なら107号・104号の両方を併記)。分岐(when)は1行も変えていない。

## 印刷(2026-09-03 に条件を変更)

設計書 §5-4 / §8-8 の「A4 1枚」「チェックボックスは空欄で印刷」は、どちらも実測で成立しなかった。

- **1枚**: A4の印字領域は269mm(297mm − 上下14mm)。共通6件だけの最小構成でも **275.9mm** で、はじめからはみ出す。
  全分岐だと510.3mm。1枚に収めるには「持ち物」8件か「窓口で聞くこと」7件を落とすしかないが、
  この紙は窓口で使うものでそちらが本体なので、落とさず **A4 2枚以内** に変えた。
- **空欄で印刷**: 集め終わったものに印をつけながら進める道具なのに、印刷すると全部空欄では紙の上で進捗が分からない。
  **状態を反映した箱**に変えた。未チェックは空箱で、その場でペンで書き込める。

実測(Playwright で印刷し、PDFのページ数と本文で確認。`npm run verify:shorui:print`):

| 条件 | ページ数 | 内容の高さ | 箱 | 印つき | 生のinput | 改ページで割れた項目 |
|---|---:|---:|---:|---:|---:|---:|
| 未回答(共通のみ) | 2 | 275.9mm | 14 | 0 | 0 | 0 / 21項目 |
| 最大(全分岐) | 2 | 510.3mm | 24 | 0 | 0 | 0 / 31項目 |
| 最大+全チェック | 2 | 505.1mm | 25 | 25 | 0 | 0 / 32項目 |

箱は `::before` の枠線だけで描いており、背景色を使っていない(背景グラフィックをオフにして印刷しても残る)。
持ち物と窓口で聞くことは、どの条件でも印刷に残る。

## 送信(2026-09-03 に条件を変更)

§8-11 の「ネットワーク送信0件」を「**回答内容を含む送信が0件**」に変えた。
`/icon.png` と、共通ヘッダー・パンくず・フッターの `<Link>` が次の画面を先読みする GET
(`/`・`/dougu`・`/privacy`)は、このページだけでは避けられない。いずれも回答内容を含まない。
このページ自身のリンク(申立書ツールへの導線)は `prefetch={false}` にした。

実測: 回答内容を含む送信 **0件** / 先読み・アイコン以外の通信 **0件** / 先読みとアイコン 4件。
