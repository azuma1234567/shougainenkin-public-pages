# Claude Code 指示書 — サイト構造の再編(地図一枚化・悩みショートカット・アプリ導線)

作成日: 2026-08-15
対象リポジトリ: shougainenkin-public-pages
対象ファイル: `lib/columns.ts` / `app/columns/page.tsx` / `app/page.tsx`(この3つ以外は原則触らない)

---

## 0. 背景と結論

ChatGPTに相談した「申請者の行動7分類」を精査した結果、7分類は採用しない。
理由: TOPページ(8ステップ)・アプリ(ガイド8段階)と別の第3の地図を持ち込むことになり、
読者に地図の翻訳を強いる。サイトはアプリへの自然な導線でもあるため、
**サイトとアプリが同じ地図を見せること**が最重要。

採用する構造は次の3層。

- **層1|背骨**: TOPの8ステップを唯一の旅の地図とする。コラムの既存9カテゴリは
  ほぼ8ステップと1:1対応済みなので、**リネームと並べ替えと少数の記事再配置**だけで実現する。
- **層2|悩みショートカット**: 段階分類は「途中から来た人」(診断書が軽い、不支給、
  カルテがない等の危機ワード流入)に効かないため、キュレーションした8本の直リンクを追加する。
  タクソノミーは増やさない。
- **層3|SEOクラスタ**: `lib/clusters.ts` の5柱設計は現状のまま。今回は一切変更しない。

## 1. 原則(全変更に優先する)

1. 既存URL・slug・ディレクトリは一切変更しない。記事の追加・削除もしない。
2. `content/columns/*.ts`(記事本文)は一切変更しない。記事タイトルも変更しない。
3. `lib/clusters.ts` は変更しない。primaryCluster / secondaryClusters も変更しない。
4. ヘッダー・フッターのナビは変更しない。
5. 変更するのは「category という表示軸」と「一覧・TOPの導線」だけ。
6. アプリへの言及は事実文1〜2行+リンクにとどめる。誘導的・広告的な文言
   (「今すぐ」「ぜひ」「おすすめ」等)は使わない。等級・受給を約束する表現は禁止。

## 2. 変更1: `lib/columns.ts` — カテゴリ軸の再編

### 2-1. ColumnCategory の新しい値(9つ・この順)

旧 → 新の対応。値そのもの(表示文字列)を置き換える。

| # | 旧カテゴリ | 新カテゴリ | 対応するTOPステップ |
|---|-----------|-----------|-------------------|
| 1 | 制度の知識 | `申請の前に` | (ステップ0=入口) |
| 2 | 初診日 | `初診日`(変更なし) | ステップ1 |
| 3 | 納付要件 | `納付要件`(変更なし) | ステップ2 |
| 4 | 相談・進め方 | `相談・進め方`(変更なし) | ステップ3 |
| 5 | 必要書類・提出 | `必要書類・提出`(変更なし) | ステップ4・7 |
| 6 | 診断書 | `診断書 — 主治医に伝える` | ステップ5 |
| 7 | 申立書 | `申立書`(変更なし) | ステップ6 |
| 8 | 審査・結果・不服申立て | `結果を待つ・不支給のとき` | ステップ8 |
| 9 | 受給後 | `受給が始まってから` | (ステップ9=旅の続き) |

`CATEGORY_ORDER` は上の表の順(申請の前に → … → 受給が始まってから)。
現状の先頭「初診日」から「申請の前に」先頭へ変わる点に注意。

### 2-2. CATEGORY_ANCHORS

アンカーidは既存のものを維持する(旧名のidのままでよい。フラグメントはSEOに影響せず、
既存の内部リンクを壊さないことを優先)。

- 申請の前に → `columns-cat-seido`(旧・制度の知識のidを継続)
- 診断書 — 主治医に伝える → `columns-cat-shindansho`
- 結果を待つ・不支給のとき → `columns-cat-shinsa`
- 受給が始まってから → `columns-cat-jukyugo`
- 他5つは現状のまま

変更後、リポジトリ全体で旧アンカー・旧カテゴリ文字列をgrepし、参照切れがないことを確認する
(`app/` 配下に日本語カテゴリ名を直書きしている箇所があれば追随させる)。

### 2-3. CATEGORY_LEADS(新設)

カテゴリ見出しの下に出す1行説明。`Record<ColumnCategory, string>` で追加する。
TOPステップとの対応を明記するのが目的(地図一枚化の要)。

```
申請の前に:            "対象になるのか、いくらもらえるのか。申請を考えはじめた人が最初に読むところ。"
初診日:                "ステップ1|最初に受診した日を確認し、証明する。"
納付要件:              "ステップ2|保険料の納付状況を確認する。"
相談・進め方:          "ステップ3|年金事務所への相談と、無理のない進め方。"
必要書類・提出:        "ステップ4・7|書類をそろえて、提出する。"
診断書 — 主治医に伝える: "ステップ5|ふだんの生活の実態を、主治医にありのままに伝える。"
申立書:                "ステップ6|病歴・就労状況等申立書を作る。"
結果を待つ・不支給のとき: "ステップ8|審査の見られ方、結果が届くまで、不支給だったときの道。"
受給が始まってから:      "更新・支給停止・額改定。受給してからの手続き。"
```

### 2-4. 記事の再配置(このリストにある slug だけ category を変更する)

移動は「入口の質問(対象になる?)に答える記事」と「不可逆(遡及時効・請求方式)を
申請前に知らせるべき記事」を `申請の前に` へ集めるため。

| slug | 旧category | 新category | 理由 |
|------|-----------|-----------|------|
| tekio-shogai-shogai-nenkin | 初診日 | 申請の前に | 「適応障害でも申請できる?」は対象可否の入口記事 |
| hattatsu-shougai | 初診日 | 申請の前に | 病名別の入口ガイド |
| hatachi-mae | 初診日 | 申請の前に | 20歳前特例=対象・制度の入口知識 |
| sokyuu-seikyuu | 審査・結果・不服申立て | 申請の前に | 遡及5年時効は不可逆★★★。申請前に知るべき |
| ninteibi-jigojusho | 審査・結果・不服申立て | 申請の前に | 認定日請求/事後重症は申請時に決める請求方式 |

上記以外の39本は category 値の文字列リネーム(2-1)のみで、所属は変えない。

再配置後のおおよその本数感(検算用): 申請の前に=11 / 初診日=4 / 納付要件=1 /
相談・進め方=3 / 必要書類・提出=3 / 診断書=13 / 申立書=7 / 結果=3 / 受給後=3。
合計44本のままであること。

納付要件が1本なのは既知で問題ない(不可逆★★★のため独立ステップとして残す。
本数の少なさは一覧の見せ方でなく今後の記事で埋める)。

## 3. 変更2: `app/columns/page.tsx` — 一覧ページの再構成

### 3-1. セクションの順序(上から)

1. **よくある悩みから探す**(新設・下記3-2)
2. **申請の段階から探す**(既存の stage-nav。新カテゴリ名・新順序に追随)
3. **テーマから探す**(既存のクラスタ details 群。位置を段階の下へ移す以外は変更しない)
4. **最新の記事**(既存のまま)
5. カテゴリ別セクション群(既存のまま。見出しの下に CATEGORY_LEADS の1行を追加)

### 3-2. 「よくある悩みから探す」ブロック(新設)

キュレーションされた固定8本。データは配列リテラルでこのファイル(または lib/columns.ts)に置く。
悩みの言葉(読者の一人称)→ 記事1本への直リンク。カテゴリやクラスタとは独立。

| 悩みラベル | リンク先 slug |
|-----------|--------------|
| 初診日がわからない・昔の病院がもうない | shoshinbi-wakaranai |
| 診断書が実態より軽く書かれた | shindansho-jittai-chigau |
| 診断書を書いてもらえない | shindansho-kaitekurenai |
| 働きながらの申請が不安 | hatarakinagara |
| 一人暮らしだと不利になる? | hitorigurashi-furi |
| 不支給になった・年金が止まった | fushikyuu-shinsa-seikyu |
| この病名でも対象になる? | taishou-shoubyou-kyoukai |
| 申請がしんどくて、進まない | shinsei-shindoi |

- 見出しは「よくある悩みから探す」、リード文は
  「申請の途中でつまずいたときは、ここから。」程度の1行。
- 表示はチップ/カード状のリンク8個。既存のデザイントーン(guide-index 等)に合わせる。
- 8本という数は増やさない(増やすとただの一覧になり、ショートカットでなくなる)。

## 4. 変更3: `app/page.tsx` — TOPと8ステップの接続

### 4-1. 各ステップから該当カテゴリへのリンク

`Step` 型に `columnsAnchor?: string`(/columns 内のアンカーid)を追加し、
各ステップ本文の末尾に次の1行リンクを出す。

文言: 「この段階の記事一覧を見る」→ `/columns#<anchor>`

対応表:

| ステップ | リンク先アンカー |
|---------|----------------|
| 1 初診日を確認する | columns-cat-shoshinbi |
| 2 保険料納付要件を確認する | columns-cat-nofu |
| 3 年金事務所へ相談・予約する | columns-cat-soudan |
| 4 必要書類をそろえる | columns-cat-shorui |
| 5 診断書の準備をする | columns-cat-shindansho |
| 6 病歴・就労状況等申立書を作成する | columns-cat-moushitatesho |
| 7 年金事務所へ提出する | columns-cat-shorui |
| 8 結果を待つ | columns-cat-shinsa |

### 4-2. アプリへの文脈CTA(自然な宣伝)

全ステップに付けない。アプリ側に対応する実体機能があるステップ1・5・6・8だけに、
事実文1行+既存のアプリリンクを置く(既にある「無料の申請ガイドアプリでも進められます」
文と重複する場合は置き換え、総数を増やしすぎない)。

- ステップ1: 「無料の申請ガイドアプリでは、いくつかの質問に答えると、いま自分が
  どの段階にいて、最初に何をすればいいかが分かります。」
- ステップ5: 「診察で話せなくても紙なら伝わります。アプリには、ふだんの生活の記録から
  主治医に渡すメモを作る機能があります。」
- ステップ6: 「アプリでは、記録した生活の様子を申立書の下書きに整理できます。」
- ステップ8: 「結果を待つあいだにできることも、アプリのガイドが段階ごとに案内します。」

トーン注意: 等級・受給の約束をしない。「〜できます」の事実文で止める。

### 4-3. TOPの「よくある悩みから探す」

ステップ群セクションの直後(FAQより上)に、3-2と同じ8本のショートカットを
コンパクトに置く(コラム一覧と同一データを共有し、二重管理しない)。

## 5. やらないこと(明示)

- 柱ページ(shougainenkin-joken 等)の新規作成・公開。これは別タスク。
  参考: 公開優先順位の合意は 条件 → 診断書 → 精神 → うつ病。
- `lib/clusters.ts` の変更、primaryCluster / secondaryClusters の変更。
- 記事本文・タイトル・description・slug・URLの変更。
- ヘッダー/フッターのナビ変更。
- 新しい計測イベントの追加。

## 6. 確認方法

1. `npx tsc --noEmit`(または `npm run build`)が通ること。
2. `npm run lint` が通ること。
3. git diff で `content/` と `app/columns/*/`(記事ディレクトリ)に差分がないこと。
4. /columns で: 悩み8チップ → 段階ナビ(新名称・「申請の前に」が先頭)→ テーマ →
   最新 → カテゴリ別、の順に表示されること。各カテゴリ見出し下にリード文が出ること。
5. TOPの各ステップ末尾から /columns の該当アンカーへ飛べること。
6. 記事44本すべてがいずれかのカテゴリに表示されること(消える記事がないこと)。
7. 旧カテゴリ名(「制度の知識」「審査・結果・不服申立て」「受給後」「診断書」単体表記)の
   文字列参照が repo 内に残っていないこと(コメントは除く)。
