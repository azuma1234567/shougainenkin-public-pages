# 「申立書を、自分で書きたい」(/dougu/moushitatesho) を利用者の順に作り直す — Codex 指示書 (2026-09-03)

## なぜ作り直すか(運営者の指摘)
アプリを移植した作りのまま。最初の画面に「読み込んでいます…」、次に「共有の端末なので保存しない」のチェック、「データを書き出す／読み込む／保存内容を削除／本当に削除しますか？」。**まだ1文字も書いていない人に管理画面を見せている。** そのあと 傷病名・発病日・初診日・生年月日 → 「本来請求／事後重症／遡及」→ やっと期間。中心の「期間を区切る」まで5画面。

## 変えないもの(検証済み・絶対条件)
- 印刷: 公式様式への重ね合わせ(最大差 0.169mm)、A4分割／A3、続紙の振り分け、はみ出し検知と8pt下限。`MoushitateshoPrint.tsx` と `data/moushitatesho/layout.ts` は触らない。
- データモデル `data/moushitatesho/types.ts` と保存 `lib/moushitatesho-storage.ts`(**保存先は変えない。既存の下書きが消えないこと**)。
- 設計書 §3 絶対条件・§11 言ってはいけないこと・§13 本文は送らない。
- 記事側の3つのカード(a4-insatsu / kikan-kugiri / kakikata)は触らない。

## 誰のために作るか
**申立書を書かなければならない人。** 半分は `moushitatesho-a4-insatsu` の記事から来る(クリックの47%)。様式はもう手元にあるか、印刷するつもりでいる。書くのが怖い。体調が悪く、一日に1画面ぶんしか進まない日がある。「事後重症」という語は知らない。

---

## §1 流れ(画面の順番)

```
0 入口          … 何ができるか、30分から、何日かに分けてよい、「はじめる」。前回の続きがあればそれを先に
1 いつから       … 発病はいつ頃 / 最初に病院に行ったのはいつ頃(2つだけ。月まででよい)
2 期間を区切る   … このツールの中心。ここに一番早く着く
3 各期間を書く   … 期間ごとに1画面(受診の有無・様子・働き方)
4 いまの状態     … 裏面の「現在」。日常生活の10項目 + 手帳
5 さかのぼりますか … 「初診から1年6か月たった頃の状態も書きますか」→ 書くなら 6 へ、書かないなら 7 へ
6 その頃の状態   … 裏面の「認定日頃」(5 で「書く」を選んだときだけ)
7 名前など       … 傷病名・生年月日など、様式の頭に要るもの(印刷の直前に)
8 印刷           … /insatsu へ
```
**「はじめる」の前に、チェックもボタンも置かない。** 書き出し・読み込み・削除は §4 の「保存について」の中へ。

## §2 各画面の文言(このまま使う)

### 画面0 入口(サーバー側で描画する。「読み込んでいます…」を出さない)
h1: **申立書を、自分で書きたい**

リード:
```
病歴・就労状況等申立書は、発病から今までを期間に分けて書く書類です。
ここでは、期間の区切り方から、各期間の書き方まで、順番に進めます。
書いた内容は公式の様式に重ねて印刷できます。手書きで出すつもりの方も、期間の整理だけ使えます。
```
3つの安心(チップ、色は使わない):
```
30分から。何日かに分けて大丈夫 ／ 書いたものはこの端末に残ります ／ サーバーには送りません。AIも使いません
```
ボタン: **はじめる**

**保存された下書きがある場合だけ**、ボタンの上に:
```
前回の続きがあります(最終保存 ◯月◯日)。
[続きから]  [新しく始める]
```
「新しく始める」を押したら「前回の下書きは消えます。よろしいですか」→ [消して始める] [戻る]。ここが削除の唯一の入口。

### 画面1 いつから
質問: **まず、2つだけ教えてください。だいたいの月で構いません。**
```
この病気や症状が始まったのは、いつ頃ですか        [年] [月]   ← 発病日
その症状で、最初に病院に行ったのはいつ頃ですか      [年] [月]   ← 初診日
```
下に1行: 「思い出せないときは空欄のままで進めます。あとで直せます。」
※ 発病日と初診日は、期間の区切りの目安(§6-1 の検知)に使うので先に聞く。傷病名・生年月日はここでは聞かない。

### 画面2 期間を区切る(中心)
見出し: **発病から今までを、いくつかの期間に分けます**
説明(3行):
```
区切りは「病院が変わった」「通わなくなった」「働き方が変わった」「暮らしが変わった」ところです。
1つの期間は3〜5年が目安。長くなったら分けてください。
最初は大まかで大丈夫。あとから足したり分けたりできます。
```
例(薄い枠で1つ):
```
例: 2015年4月〜2017年3月  A病院に通院。会社勤め
    2017年4月〜2019年12月 通院を中断。退職して実家
    2020年1月〜現在        B病院に通院。就労支援に通う
```
期間の行: [開始 年/月] 〜 [終了 年/月 または「現在」] 。「期間を追加する」「日付順に並べる」。5つを超えたら「6つ目からは続紙に載ります」を静かに1行(既存の挙動)。
既存の検知(発病より前・空白・60か月超)はそのまま、文言は責めない形に:「この期間は5年を超えています。分けると書きやすくなります」。

### 画面3 各期間を書く(期間ごとに1画面。上に「期間 2 / 4」)
見出し: **◯年◯月〜◯年◯月のこと**
```
この期間、病院に行きましたか        [行った] [行かなかった]
→ 行った:  病院の名前(分かる範囲で)  [       ]
            どんな治療・どんな様子だったか  [自由記述、縦に伸びる]
→ 行かなかった: なぜ行かなかったか、その間どう過ごしていたか  [自由記述]
この期間、働いていましたか          [働いていた] [働いていなかった]
→ 働いていた: 仕事の内容と、つらかったこと・配慮してもらったこと  [自由記述]
```
入力欄の下に、既存のはみ出し検知(「この枠はあと2行ほどで埋まります」「この枠に収まりません。続紙へ送るか、期間を分けると収まります」)。
書き方のヒントを1つだけ、折りたたみで: 「書けないときは: いつ・どこで・何が・どれくらい、の順に短く」

### 画面4 いまの状態(裏面「現在」)
見出し: **いまの生活のことを教えてください**
日常生活の10項目は、`/dougu/mitate` の作り直し(`docs/mitate-redesign-2026-09-03-instructions.md` §2)と**同じふつうの言葉・同じ4択**を使う(正式名は小さく)。手帳は「障害者手帳を持っていますか [持っている/持っていない/申請中]」。

### 画面5 さかのぼりますか
質問: **初診日から1年6か月たった頃の状態も、書きますか**
説明:
```
その頃の状態を書くと、その時点までさかのぼって請求できる場合があります(認定日請求)。
その頃の診断書も必要になります。分からなければ「あとで決める」で進めます。
```
選択肢: [書く] [書かない(いまの状態だけで請求する)] [あとで決める]
※ 内部の `seikyuuType`(本来／事後重症／遡及)への対応: 書く=遡及、書かない=事後重症、あとで決める=未定(両方の裏面を出さず、印刷前にもう一度聞く)。**語は画面に出さない。**

### 画面6 その頃の状態(画面5で「書く」のときだけ)
見出し: **初診日から1年6か月たった頃(◯年◯月ごろ)の生活のこと**
画面4と同じ項目。

### 画面7 名前など(印刷の直前)
見出し: **最後に、様式の頭に入るものを**
```
病名(診断書に書かれている名前)  [       ]
生年月日                        [年][月][日]
```
「分からない欄は空欄のままで印刷して、手書きできます。」

### 画面8 印刷
既存のまま(「入力した内容を、公式様式の位置に重ねて印刷します。空欄はそのまま手書きできます。」「印刷プレビューを開く」)。
その下に「ここからできること」: → どこに出せばいい？(/dougu/madoguchi) / → 何をそろえればいい？(/dougu/shorui)。

## §3 全画面に共通
- 上端に細い進捗バー(現在地だけ。「あと◯%」は出さない。設計書 §5)。
- 下に静かな1行「ここまでの内容は、この端末に残っています」(保存が効いているとき)。localStorage が使えないときは「この端末では保存できません。閉じると消えます」。
- 「戻る」「次へ」。必須で止めない(空欄のまま進める)。
- 「中断する」は右上に小さく。押したら「ここまでの内容は残っています。いつでも続きから始められます」→ 申請の流れ(/shinsei)へ。

## §4 「保存について」(1か所にまとめる)
画面8 の下に折りたたみ「保存について」を置き、その中にだけ:
```
下書きをファイルに書き出す(別の端末に持っていく)
ファイルから読み込む
共用のパソコンなので、この端末に残さない  [チェック]
この端末の下書きを消す → 確認
```
入口の画面には出さない。

## §5 消すもの
- 「読み込んでいます…」(入口はサーバー描画。保存データの有無だけクライアントで差し替える)
- 入口のチェックボックスと 書き出し／読み込み／削除／削除確認
- 「本来請求／事後重症／遡及」の語(画面から。内部の値は残す)
- 「基本」を最初に置く構成(傷病名・生年月日は最後へ)
- 「裏面(認定日頃)」「裏面(現在)」という見出し語(様式の呼び方は印刷側だけ)

## §6 見た目
- `/dougu/mitate` の作り直しと同じ: primary(#0284c7)1色と灰色。黄色い箱・緑の帯・グラデーションは使わない。
- 質問 20〜22px、入力欄は全幅、自由記述は縦に伸びる(内側スクロールにしない。設計書 §12)。
- 1画面1トピック。長いスクロールを作らない。
- 文字 16px 未満を使わない。ダークモード追随、印刷は白地黒文字(既存)。

## §7 検証(番号つきで全部○×。×は直さずに報告)
1. 入口が「読み込んでいます…」なしで、サーバー描画のHTMLに h1 とリードと「はじめる」が含まれる
2. 「はじめる」の前に、チェック・書き出し・読み込み・削除が無い
3. 保存済みの下書きがあるとき、入口に「続きから／新しく始める」が出て、「続きから」で内容が復元される(既存の保存形式のまま)
4. 「本来請求」「事後重症」「遡及」「裏面」「認定日頃」が画面のテキストに出ない
5. 期間を区切る画面が、入口から数えて3画面目
6. 画面5 の3択が内部の seikyuuType に正しく対応し、印刷で出る裏面が変わらない(既存の verify-moushitatesho #6 続紙と印刷の検査が通る)
7. はみ出し検知の文言が出る。8pt 下限と警告(既存 #8)が通る
8. 印刷の重ね合わせ(既存 #4)が通る。`MoushitateshoPrint.tsx` と `layout.ts` に差分0
9. localStorage 無効でも入口→印刷まで進める(既存 #10)
10. 375px で横スクロールなし。キーボードで最後まで(既存 #12)
11. 回答内容を含む送信0件
12. 記事側の3カードがバイト一致
