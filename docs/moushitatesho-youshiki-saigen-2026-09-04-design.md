## §1 いま何が起きているか(検証結果の読み直し)

前回の検証は「1mm以内 ○」だったが、測っていたのは**背景の罫線**だけだった。背景は公式PDFを画像にしたものなので、罫線が合うのは当たり前で、**入力した文字が様式のどこに入るか**は一度も検証されていない。実際の出力(`docs/verification/dougu-moushitatesho-2026-09-03/png/minimal-a3-1.png` ほか)を見ると:

| 症状 | 原因(`components/tools/MoushitateshoPrint.tsx` と `data/moushitatesho/layout.ts`) |
|---|---|
| 発病日の欄に「2020年1月1日」が2つ、初診日の欄は空 | `layout.ts` が発病日・初診日を**縦に並ぶ2行**として持っている(`hatsubyou y:51`, `shoshin y:60`)。実物は**同じ行に左右**に並ぶ |
| 日付が「昭和・平成・令和 年 月 日」の印字に重なって印字される | 日付を「2021年2月〜2021年2月」という**1つの文字列**として欄の左上に置いている。様式は元号を○で囲み、年・月・日の**空欄に数字を置く**作り |
| 「受診した」に○がない。医療機関名が空 | 受診の有無を「受診した：医療機関1」という**文字列**で書いている。様式は「受診した・受診していない」のどちらかを○で囲み、医療機関名は「医療機関名」の右の線上に書く |
| 期間の状況の本文が枠の左1/3にしか入らず、8ptまで縮む | 本文枠の幅が実測より狭い(170mm指定だが、実測は 173.5mm)うえ、収まらないと**自動で8ptまで縮小**している(設計書§7「勝手に縮小しない」に反する) |
| 裏面がほぼ白紙(職種・通勤・出勤日数・理由ア〜オ・日常生活の1〜4・手帳・請求者・日付がすべて空) | `MAIN_BACK` に傷病名・その他・氏名の3欄しかない。裏面の**ほぼ全部が未実装** |
| 「1．障害認定日（ 年 月 日）頃」の日付が空。「2．現在（請求日頃）」に別の文字が重なる | 裏面の見出し行の欄が未定義 |
| 続紙が5行×表面のみ | 実物の続紙は**表5行・裏6行**、裏に申立・請求者欄がある。現在は裏面を印刷しない |
| No. ― 枚中 が空 | 未実装。記載要領は「1枚目→No.1－2枚中、2枚目→No.2－2枚中」 |

つまり**「様式の画像の上に、文字列を数か所貼っている」**状態で、「様式に記入した紙」にはなっていない。これを、**欄ごとに「数字を置く/○で囲む/文章を流し込む」の3種類で記入する**作りに変える。背景の様式画像は正しいので、そこは活かす(ただし画像の形式は§3で変える)。

## §2 目標と前提

### 2-1 目標(これが「全く同じもの」の定義)

日本年金機構の公式様式(`01.pdf`、A3 297×420mm、表裏)と続紙(`03.pdf`、A4 210×297mm、表裏)に、**次の3通りで記入した状態**を、ブラウザの印刷で原寸再現する。

1. **数字を置く** — 年・月・日、時間・分、出勤日数、級、No.、枚中、続紙の通番。印字された「年」「月」「日」の**左の空欄の中央**に置く。
2. **○で囲む** — 昭和・平成・令和、受診した・受診していない、ア〜オ、着替え〜買物の1〜4、手帳の1・2・3、身・精・療・他。印字された文字の**中心に楕円**を描く(手書きで○を付けたのと同じ見え方)。記載要領の「『受診した』を〇で囲んで」に合わせる。
3. **文章を流し込む** — 傷病名、医療機関名、期間の状況、職種、通勤方法、身体の調子、その他、手帳名、障害名、住所、氏名、電話、続柄。欄の**内側**に、印字された見出しと重ならない位置から、明朝10.5ptで流す。

**縮小はしない。**収まらなければ「収まらない」と伝えて、期間を分けるか続紙へ送る(現行設計§7のとおり)。文字の大きさは書類全体で1つだけ選べる(標準10.5pt / 小さめ9pt。§6-3)。

### 2-2 公式ファイルの置き場所

`docs/forms/moushitatesho/` に次を置く(git管理。改版に気づけるように md5 を `README.md` に書く)。配布元: https://www.nenkin.go.jp/shinsei/jukyu/shougai/shindansho/20140516.html (更新日 2025年10月20日)。

## §3 作り

### 3-1 背景: PDF→SVG

いまの背景は300dpiのPNG(表裏 各3508×4961px、合計3MB超)。印刷で罫線が甘くなり、読み込みも重い。公式PDFは**すべてベクター**(文字はアウトライン化、フォント埋め込みなし)なので、そのままSVGにする。

```
pdftocairo -svg -f 1 -l 1 docs/forms/moushitatesho/01.pdf public/forms/moushitatesho/main-1.svg
pdftocairo -svg -f 2 -l 2 docs/forms/moushitatesho/01.pdf public/forms/moushitatesho/main-2.svg
pdftocairo -svg -f 1 -l 1 docs/forms/moushitatesho/03.pdf public/forms/moushitatesho/cont-1.svg
pdftocairo -svg -f 2 -l 2 docs/forms/moushitatesho/03.pdf public/forms/moushitatesho/cont-2.svg
```

- `<img src>` ではなく **`background-image: url(...svg)`** のまま、`background-size: 297mm 420mm`(続紙は `210mm 297mm`)。拡大率に依存しない。
- SVGに `width="297mm" height="420mm"` が入っていることを確認する(pdftocairo は pt で出すので、必要なら `viewBox` を残して width/height を mm に書き換える)。
- PNG は消す。変換したSVGのサイズを報告する(1枚 数百KB 以下のはず)。

### 3-2 レイアウト: 3種類のスロット

`data/moushitatesho/layout.ts` を全面的に書き直す。**§4 の寸法表を、そのまま定数にする。**コンポーネントに数値を直書きしない。

```ts
export type TextSlot   = { kind: "text";   x: number; y: number; w: number; h: number; pt?: number; lines?: number; align?: "left"|"center"; valign?: "top"|"middle" };
export type DigitsSlot = { kind: "digits"; cx: number; cy: number; w: number; pt: number };   // 中央揃え
export type CircleSlot = { kind: "circle"; cx: number; cy: number; rx: number; ry: number };
```

- 単位はすべて **mm**、用紙の左上が原点。
- `text` の既定は 10.5pt、行送り 1.35(=5.0mm)、`valign:"top"`。
- `digits` は数字だけ。全角ではなく**半角数字**。空欄に入りきらない長さは想定しない(年は最大2桁、月日は2桁、時間・分・日数は2桁、級は1桁、No・枚中は2桁)。
- `circle` は SVG の `<ellipse>` を1本の線(0.35mm、黒)で描く。塗らない。

### 3-3 描画: 1つの関数で全部の紙を作る

`components/tools/MoushitateshoSheet.tsx` に `renderSheet(kind: "main-front"|"main-back"|"cont-front"|"cont-back", values)` を1つ作り、**画面のプレビューと印刷で同じDOMを使う**(現行どおり。別に作ると必ず食い違う)。

- 本文の `.mt-slot-text` は `position:absolute; white-space:pre-wrap; overflow:hidden; word-break:break-all; line-break:strict`。フォントは `"MS Mincho","MS 明朝","Yu Mincho","YuMincho","Hiragino Mincho ProN",serif`(様式の印字が MS-PMincho なので明朝で揃える)。
- `.mt-slot-digits` は `text-align:center`、`transform: translate(-50%,-50%)` で `cx,cy` に中心を合わせる。
- 元号は `2019-05-01` 以降を令和、`1989-01-08` 以降を平成、`1926-12-25` 以降を昭和で判定し、年は元号年(令和元年は「1」)。判定は `lib/wareki.ts` に置き、テストを付ける(境界日4つ)。
- `from`/`to` は現行どおり `YYYY-MM`(月まで)。**「日」は空欄のまま**印刷する(入力していないものは書かない)。
- **自動縮小(`FIT_BASE_PT`〜`FIT_MIN_PT`のループ)は削除する。**はみ出しは§6-3で扱う。

## §5 記入の規則(様式の側の決まり)

## §7 続紙と枚数

### 7-1 割り付け

- 本紙 表: 期間1〜5。
- 続紙 k(k=1,2,…): 表に 6〜10、裏に 11〜16 … 一般に `5 + 11(k−1) + 1` から。裏が空なら裏は印刷しない。
- 通番は通しで書く(本紙は印字済み、続紙は digits で書く)。
- No.: 本紙 1、続紙 k は k+1。枚中: 1 + 続紙枚数。**総枚数が 1 のときは両方とも空欄**(2026-09-04 指示書 §2)。

### 7-2 続紙の裏の申立・請求者欄

続紙の裏にも「上記のとおり相違ないことを申し立てます」と請求者・代筆者の欄がある。**本紙の裏と同じ値を書く。**(1枚ごとに申立の体裁が完結する様式のため。`05.pdf` に別の指示があればそれに従い、報告に書く。)

## §9 検証(前回やらなかった「文字の位置」を測る)

### 9-1 公式PDFの測り方(再現できる手順)

`scripts/measure-form.py`(Python、pdfplumber)を repo に置き、`03.pdf` の続紙を測って §4-4 の空欄を埋める。要点:

```python
import pdfplumber; mm=lambda v:v/72*25.4
p=pdfplumber.open('docs/forms/moushitatesho/03.pdf').pages[0]
# 罫線: p.lines / p.rects を mm に変換して並べる
# 実文字(元号など): p.chars の x0/top/x1/bottom
# アウトライン文字(見出し): p.curves の外接矩形を、縦に重なるもの同士でまとめて「行」にし、2.2mm超の隙間で「語」に分ける
```

測った値は `layout.ts` に写し、`docs/verification/moushitatesho-youshiki-2026-09-04/measure-cont.md` に**行ごとの座標の一覧**を残す(次の改版で差分が取れるように)。

### 9-2 文字の位置の検査(これが本命)

`scripts/verify-moushitatesho-layout.mjs`。Playwright(Chromium)で印刷画面を **A3 原寸で PDF に出し**、pdfplumber(または pdf.js)で**自分たちが描いた文字の外接矩形**を取り、次を全欄で確認する。

1. 文字の矩形が、`layout.ts` のスロット矩形の**内側**にある(はみ出し 0)。
2. 文字の矩形が、公式PDFの**印字と交差しない**。
   ~~印字の矩形は §9-1 の方法で `01.pdf`/`03.pdf` から抜き、`official-glyphs.json` に置く。~~
   → **公式PDFを300dpiで描画した画素で判定する**(2026-09-04 指示書2 §4)。`01.pdf` は
   クリップされて描画されない塗り図形を content stream に持っており(年・月・日の空欄の中にもある)、
   オブジェクト一覧で判定すると偽の衝突が出るため。`official-glyphs.json` は記録として残す
   (○で囲む字の中心を出すのに、実文字のあるところでは今も使っている)。
3. digits の中心が、印字された「年」「月」「日」等の**左隣の空欄の中央**から ±1.0mm 以内。
4. circle の中心が、囲む文字(令和・受診した・ア・1 など)の中心から ±0.5mm 以内、楕円が文字を完全に含む。
   ~~含むかどうかは rx ≧ 半幅×√2 かつ ry ≧ 半高×√2 で見る。~~
   → **`(a/rx)² + (b/ry)² ≤ 1/1.03²`**(a=字の半幅, b=字の半高。2026-09-04 指示書2 §1)。
   中心を共有する楕円が長方形を含む条件は**角の1点だけで決まる**。√2 の式は十分条件にすぎず、
   実際より約1.4倍厳しい。これで測ると §4 の半径のうち直す必要があるのは元号と受診の系統だけだった。
   右辺の 1/1.03² は「半径換算で3%の余裕」を数式にしたもの。
5. 期間の状況の本文が、枠の右端 279.1mm(続紙は 188.9mm)を超えない。

サンプルは5つ: `empty`(全部空)、`minimal`(表1期間・裏S=0)、`typical`(3期間・裏S=0/S=1両方・手帳①・代筆者なし)、`seven`(7期間→続紙1枚、裏あり)、`max`(16期間→続紙2枚、全欄最長、絵文字・URL・半角英数・改行20回混在)。

### 9-3 目で見る検査

各サンプルを `png/` に出し、**公式PDFに 50% で重ねた画像**も出す。前回と違い、**記入済みの状態**で重ねる。RESULT.md に貼る。

### 9-4 エクセル版との照合

`02.xlsx` `04.xlsx` を LibreOffice で PDF に出し(`soffice --headless --convert-to pdf`)、同じ入力をこのツールで出したものと**並べて**見る。合わせるのは「文字がどの欄のどのあたりに入るか」「文字の大きさの感じ」。罫線のずれは追わない(エクセル版とPDF版は微妙に違う。**PDF版が正**)。差があれば RESULT に書き、直すかどうかは東さんが決める。

## 執筆メモ(サイトに載せない)

- 前回の検証が「1mm以内 ○」で通ったのは、背景画像の罫線しか測っていなかったから。**検査は「入力した文字がどこに入ったか」を測らないと意味がない。**§9-2 はそれを直したもの。
- 元号を○で囲む方式にしたのは、記載要領の文言(「〇で囲んで」)と、手書き・パソコンのどちらの提出物とも同じ見え方になるため。エクセル版が別の方式(選んだ元号だけ印字など)でも、PDF版の様式に○を付けた紙は窓口で通る。
- 「日」を空欄にするのは、入力していない値を書かないという原則のため。日を「1」で埋めると、それは書類上の虚偽になる。
- 文字の大きさを書類全体で1つにしたのは、欄ごとに違う大きさの紙は「詰め込んだ」印象になるため。
